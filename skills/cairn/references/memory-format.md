# 记忆格式说明

本文说明个人数据仓库中各类页面与学习记录的目录职责、命名与写入格式。保存原则、归属边界与行动效力以 `SKILL.md` 第五节为准。

## 目录与职责

| 路径 | 职责与容纳内容 |
|---|---|
| `settings/general.md` | 通用设定（常驻全文）：个人背景自述、长期方向、每轮均需遵循的高频教学约定与工作流简短入口指针 |
| `settings/projects/<项目>.md` | 项目设定（匹配项目时加载全文）：该项目的目标、使用条件、期限、专门教学分工及逻辑材料/工作区位置 |
| `settings/<子目录>/<名称>.md` | 按需设定（如 `workflows/`、`templates/`，加载时仅返回路径与 `summary`）：外部工具协作、材料与归档工作流、个人笔记重点原则及各类输出模板；按实际复杂度建立，不预建空文件 |
| `state/progress/<项目>.md` | 学习进度：材料与工作区位置、进展概况、当前工作状态、学习者要求保留的备忘及已确定的下一步安排 |
| `state/mastery/` | 掌握状态：按可复用概念、机制或能力组织的最新能力边界判断及依据 |
| `state/traits/` | 学习特征：带观察范围、随新表现修订的跨内容认知与辅导假设 |
| `records/YYYY-MM-DD.md` | 学习记录：按日期归档、只追加的事件流，由服务端拼装头部元数据 |
| `paths.local.toml` | 本机目录索引（`.gitignore` 忽略，服务端只读解析）：逻辑目录名到本机物理路径及 `read` / `read-write` 边界的映射 |

## 名称与摘要规范

- **学习项目名称与 `settings/` 子目录名称**：仅使用小写 ASCII 英文字母、数字和连字符 `-`（如 `cs336`、`vllm`、`workflows`、`templates`）。
- **学习状态页面名称**：去掉 `.md` 的文件名即为页面名，可使用中英文、数字、空格和圆括号，不超过 80 个字符，不得包含 `/ \ : * ? " < > | # ^ [ ]`。名称在整个 `state/` 下不区分大小写唯一。
  - **命名倾向**：优先沿用 `start_session` 掌握状态名称清单中已有的同义概念名称；新建 `mastery/` 页面时以**可跨项目复用的概念、机制或能力**命名（如 `缩放点积注意力`、`内存合并访问`），避免按单次作业或章节号命名。
- **设定页面名称与标识**：按需设定文件名推荐使用小写 ASCII 字母、数字和连字符 `-`（如 `workflows/note-guide`、`templates/paper-note`，中文用途写在 `summary` 中），亦兼容上述合法中英文页面名；在 `settings/` 内不区分大小写唯一。调用 `read_pages` 或跨目录引用时写作 `settings/<相对路径>`；调用 `update_settings` 时 `page` 传相对于 `settings/` 的路径（如 `general`、`projects/<项目>`、`workflows/note-guide`）。
- **frontmatter `summary`**：所有页面顶部必填单行 `summary`（不超过 200 个字符），概括页面最新核心内容。重写或局部编辑导致核心认识或位置变化时同步更新摘要，保留关键支持条件与暂定性质，移除已过时的旧信息；其余已有 frontmatter 字段原样保留。

## 各类页面的正文写法

### 1. 掌握状态（`state/mastery/`）

页面粒度以“能清晰命名指称、能独立更新、能用一两句话概括”为准；一个页面可包含围绕同一概念的多项维度（如原理解释与代码实现）。

每项判断综合历次表现写出最新结论：
- **当前能力边界**：在什么任务与资源条件下能做到什么（严格区分学习者独立产出的部分与模型提示或顺势补全的部分）。
- **核心依据**：支撑当前判断的关键表现发生日期、任务背景、实际支持条件及来源（当场直接观察，或学习者事后自述）。
- **确信度说明**：仅在观察较少、情境单一等因素影响后续教学选择时简要注明原因。

新表现已经超越早期局部错误时，直接合成更新为当前水平（早期卡点最多保留半句演变背景或直接省略），不按时间堆叠每次历史细节；与当前明确目标直接相关的已观察差距注明对应目标；不列出“尚待观察 / 待加强”清单。

示例：
```markdown
---
summary: 能无提示推导缩放点积注意力与缩放因子原理；能在查阅文档条件下独立实现因果掩码并自行核对高维广播形状。
---

# 缩放点积注意力

关联页面：[[多头注意力]]、[[因果掩码]]。

- **原理解释**：能无提示说明点积方差随 $d_k$ 增长导致 softmax 梯度饱和的机制。依据：2026-11-12 初学解释，2026-11-19 间隔一周分析推理缓存时再次独立准确调用。
- **实现与广播对齐**：能在查阅文档条件下独立写出注意力与掩码实现。依据：2026-11-14 初次实现曾需提示检查最后两维形状，2026-11-20 重构解码模块时已能主动列出四维形状并一次通过单测。
```

### 2. 学习特征（`state/traits/`）

只记录跨具体知识点可迁移、对后续新项目有参考价值的归纳（如有效的认知切入顺序、跨主题反复出现的执行习惯或盲区、自我评估高估或低估倾向），不重复单个知识点的掌握情况。每条写明归纳内容及已观察到的项目与时间范围；曾观察到反例时如实注明例外（未出现反例则不写），不附加“待后续检验”等计划性表述。常规保持在一两页精炼规模。

### 3. 学习进度（`state/progress/`）

依项目性质按章节、里程碑或主题组织，包含：
- **基本信息与材料定位**：记录项目材料与工作区位置——使用默认材料通道时写相对路径（文件如 `week03/lec05.pdf`，目录以 `/` 结尾如 `lab1/`，未登记的默认通道文件在加载时会被报告为新材料）；使用外部目录或在线资源时写逻辑目录名加相对路径（如 `materials: cs336/lectures/`、`workspaces: cs336/lab1/`）或外部链接，不硬编码盘符或挂载点。
- **进展概况**：已完成与进行中的部分（任务完成是进度事实，对应能力记入 `mastery/`）。
- **当前工作状态**：如实说明停在哪个章节、模块或步骤；若任务处于中途暂停，一并陈述对恢复脉络有价值的客观尝试结果（如已核对排除的方向）、标明来源与暂定性质的当前分析认识、上一轮正在开展的局部步骤，或学习者提出留下的原问题。顺畅完成一节时只写位置。
- **备忘与已确定的下一步**（可选）：学习者明确要求“先记下来备查”的选项或问题注明为学习者备忘（仅供后续参考）；学习者明确决定的下一步执行安排写作 `学习者决定：……`。均无时省略本项，不设固定的“未决问题”或“模型候选建议”栏目。

### 4. 学习者设定（`settings/`）

保存学习者的个人背景自述，以及明确采用的目标、使用条件、教学约定、外部工作流规则与输出格式模板：
- **控制常驻边界与按需拆分**：`general.md` 仅保留背景自述、长期方向、每轮均需遵循的高频约定与工作流简短入口指针，不内联存放外部工具细则或模板正文。不预先创建空的子目录或空模板页；外部工作流或输出规范简单时单页存放，变复杂时在停顿处说明结构并经确认后用 `update_settings` 拆分为子目录多页面（如 `workflows/` 存放外部协作与梳理总则、`templates/` 存放具体输出模板），在上层页面写明引用指向（如 `settings/templates/paper-note`）。
- **外部协作集中维护与逻辑路径引用**：外部服务分工与输出流程集中维护，不在各项目页与模板页分散重复；引用外部目录时统一使用 `paths.local.toml` 中的逻辑目录名加相对路径（如 `notes: Courses/<项目>/`），不硬编码盘符或本机绝对路径。
- **确认与重组**：所有设定页的新建、修改、重命名（`new_page`）与删除（`remove`，`general` 不可删除）均仅在学习者明确提出或确认后，通过 `update_settings`（附带如实填写的 `confirmation` 说明）执行；具体适用条件或有效期限直接写在对应条目中。

## 学习记录与双链

- **追加记录**：调用 `add_record_entry` 时只传正文 `text`（及可选的 `project`、`conversation`），时间与前置标记由服务端生成。正文用第三人称简明写清：学习者自己完成了什么、你或材料提供了什么支持（含顺势补全的推理）、结果如何，或学习者作出了什么决定。发现过往记录有误时，追加一条注明原日期时间的更正记录，并同步修正相关状态页。
- **双链 `[[页面名]]`**：支持 `[[页面名]]`、`[[页面名|显示文字]]` 与 `[[页面名#标题]]`（代码块与行内代码内不解析）。在进度页与相关状态页中使用准确页面名建立双链，供 `start_session` 召回当前项目关联的状态摘要及供 `get_related_pages` 查找上下文。
- **时间信息无需手写维护**：各状态页的首次创建日期、最近更新日期和累计更新天数由服务端从文件 git 内容变更历史（排除 `move_page`、`remove_page` 的重命名与双链改写提交）中计算得出，作为识别较久未更新页面的线索；具体表现的发生日期写在判断依据正文中。新建状态页直接调用 `write_page`；修改已有状态页前先用 `read_pages` 获取最新内容与 `base_version`，版本冲突时基于返回的最新内容整合后重试。
