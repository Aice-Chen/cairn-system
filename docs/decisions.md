# 议题与决策

本文记录基础版设计的过程：设计的修改方式，各项议题的状态，暂缓的事项，以及后续步骤。文档的整体结构见[文档总览](README.md)。

## 修改的方式

基础版的设计以 `docs/` 下的各份文档为准，修改按以下方式进行。

1. 一项修改对应一个议题，以 PR 提出，同时更新对应的文档和本文中该议题的状态。
2. 文档中内容的效力以本文的状态为准。“已确认”的内容是后续设计和实现的依据，修改它需要重新确认；“提案”是当前的工作稿，经维护者确认后改为“已确认”。
3. 新的想法先在本文登记，写明它要解决的问题，进入讨论后再展开设计。登记时的状态为“待讨论”；不属于基础版范围的，列入“暂缓的事项”。
4. 一项机制是否加入基础版，按设计哲学第 7 条的条件判断（见[目标、边界与设计哲学](design/goals-and-principles.md)）：缺少它时基础流程无法完成，或者实际使用中已经出现它要解决的问题。

现行版本（v1）的修改仍按根目录 [DESIGN.md](../DESIGN.md) 中“修改系统的方式”进行。

## 议题

状态分为四种：**已确认**，**提案**（已有方案，尚待确认），**待讨论**（已登记问题，尚无方案），**暂缓**（不在基础版范围内，单独列于下一节）。

## 暂缓的事项

以下事项不在基础版的范围内。每项写明它要解决的问题和重新考虑的条件。

| 事项 | 要解决的问题 | 重新考虑的条件 |
|---|---|---|
| 记忆整理 | 跨越多次对话，对学习状态作整体的重新评估：合并零散的页面，发现相互矛盾或已经过时的判断 | 页面数量增长后，过时或矛盾的判断开始影响辅导 |
| 对话之间的变更通知 | 一个对话得知其他对话对记忆所作的更新 | 实际使用中出现依据过时的页面进行教学的情况 |
| 时间信息的细化 | 区分“学习”与“检验”两类涉及；由服务端提示间隔较长的内容 | 试用后，模型利用现有时间信息安排检验的效果不足 |
| 笔记生成与模板 | 按模板为学习者生成笔记；确定模板在插件和数据仓库中的位置 | 基础版可用之后 |
| 教学效果评估 | 评估辅导是否促进了长期掌握 | 试用之后 |
| 其他学习类型的学习方法 | 实践项目、源码阅读、论文阅读的学习方法 | 基础版可用之后，先行调研 |
| 2026 年 10 月重构方案中的机制 | 结构化的证据、会话记录与自动接续、跨对话的回顾等 | 对应的问题在实际使用中出现时，从讨论记录中取用 |

## 后续步骤

1. **确认设计。** 逐项确认上表中的提案，有异议的部分先行修改。
2. **详细设计。** 按指引定稿、记忆格式规格、工具规格、课程与书籍的学习方法的顺序逐项进行，每项确认后再进入下一项。
3. **实现。** 在 v1 服务端的基础上修改，组织插件包，先完成本地方式。实现阶段同时进行各客户端的实测（包括对话标识的来源）和开源准备（许可证、模板仓库、安装文档、示例数据）。
4. **试用。** 用基础版进行实际学习，记录出现的问题，据此决定扩展模块的顺序。
