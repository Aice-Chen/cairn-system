# 议题与决策

本文记录基础版设计的过程：设计的修改方式，各项议题的状态，被取代的结论，暂缓的事项，以及后续步骤。文档的整体结构见[文档总览](README.md)。

> **本版本的性质。** 本分支是 Claude 撰写的一版完整方案，与 ChatGPT 在 `docs/shared-learning-model-20261119` 分支上撰写的方案并行，供学习者对比和结合。两版共同的出发点，是 2026-11-19 确认的共同学习模型和清单收敛（见下文“已确认”的前三项）。本版的具体内容均为提案，列在“提案”一节。

## 修改的方式

基础版的设计以 `docs/` 下的各份文档为准，修改按以下方式进行。

1. **一项修改对应一个议题。** 以 PR 提出，同时更新对应的文档和本文中该议题的状态。
2. **效力以本文的状态为准。**
   - “已确认”的内容是后续设计和实现的依据，修改它需要重新确认。
   - 被新结论取代的内容，移入“已被取代或部分失效的结论”，并说明取代关系。
   - “提案”是当前的工作稿，经学习者确认后改为“已确认”。
3. **新的想法先登记。** 新的想法先在本文登记，写明它要解决的问题，状态为“待讨论”，进入讨论后再展开设计；不属于基础版范围的，列入“暂缓的事项”。
4. **新增机制的条件。** 一项机制是否加入基础版，按设计哲学第 7 条判断（见[目标、边界与设计哲学](design/goals-and-principles.md)）：缺少它时基础流程无法完成，或者实际使用中已经出现它要解决的问题。
5. **使用中发现的问题按性质归位。**
   - 学习者的选择和约定，由学习者写入设定，不修改插件。
   - 可以在不同学习者之间复用、适用条件明确的经验，整理为学习方法。
   - 模型反复出现的不当做法，写入指引，并写明所针对的现象（见[技能](components/skill.md)中的“指引的写法”）。
   - 需要增加机制的，按第 4 条判断；不满足条件的，列入暂缓的事项。

现行版本（v1）的修改，仍按根目录 [DESIGN.md](../DESIGN.md) 中的“修改系统的方式”进行。

## 议题

议题的状态分为四种：**已确认**；**提案**，即已有方案、尚待确认；**待讨论**，即已登记问题、尚无方案；**暂缓**，即不在基础版范围内，单独列于下文。

## 暂缓的事项

以下事项不在基础版的范围内。每项写明它要解决的问题和重新考虑的条件。

| 事项 | 要解决的问题 | 重新考虑的条件 |
|---|---|---|
| 记忆整理 | 跨越多次对话，对学习状态作整体的重新评估：合并零散的页面，发现相互矛盾或已经过时的判断 | 页面数量增长后，过时或矛盾的判断开始影响辅导 |
| 对话之间的变更通知 | 一个对话得知其他对话对记忆所作的更新 | 实际使用中出现依据过时的页面进行教学的情况 |
| 时间信息的细化 | 区分接触内容、尝试运用和取得证据等不同的涉及；由服务端提示间隔较长的内容 | 试用后，模型利用现有的时间信息安排回忆和再次运用的效果不足 |
| 笔记生成与模板 | 按模板生成笔记，从各客户端保存梳理的成稿，笔记之间的链接；确定模板在插件和数据仓库中的位置 | 基础版可用之后 |
| 教学效果评估 | 评估辅导是否促进了目标能力的形成和保持 | 试用之后 |
| 项目结束后的回顾 | 学习项目结束后，其中的内容只在之后的学习再次涉及时才会被运用，系统不会主动提出 | 试用中学习者希望对已结束项目的内容得到提醒 |
| 2026 年 10 月重构方案中的机制 | 结构化的证据、会话记录与自动接续、跨对话的回顾等 | 对应的问题在实际使用中出现时，从讨论记录中取用 |

## 后续步骤

1. **对比结合两版方案。** 当前步骤。对比本版与 ChatGPT 的方案，形成一版，确认后合并。
2. **工具规格。** 确定各工具的参数、返回结构、错误情形和说明文字；指引中涉及工具的句子随之确定。
3. **实现。** 在 v1 服务端的基础上修改，组织插件包，先完成本地方式；同时进行各客户端的实测和开源准备。
4. **试用。** 用基础版进行实际的学习，按“修改的方式”第 5 条处理使用中发现的问题。学习方法和扩展模块依据实际出现的问题加入。
