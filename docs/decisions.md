# 议题与决策

本文记录基础版设计的过程与结论状态：修改治理规则、当前有效的确认与整合结论、历史替代关系、暂缓的扩展事项以及下一步计划。系统全貌见[文档总览](README.md)。

## 修改治理规则

基础版设计以 `docs/` 与 `skills/cairn/` 下的当前文档为准，按以下规则演进：

1. **按议题变更**：每次实质设计调整对应明确的议题与理由，通过分支与 PR 提交，同步更新正文与本文的决策状态。
2. **状态效力**：
   - **已确认**：经学习者确认的设计基线，后续实现与细化以其为准；若需推翻或实质修改，须单独说明原因并重新确认。
   - **本轮整合修订**：根据最新讨论确认的方向落成完整文本、供最终审阅合入的内容。
   - **已被取代的结论**：移入“历史决策与替代说明”，保留演变脉络，不再作为实现依据。
3. **新增机制的准入门槛**：遵循[目标、边界与设计哲学](design/goals-and-principles.md)第 7 条——只有“缺少它基础闭环无法跑通”或“实际使用中已反复暴露对应问题”时才引入新机制，其余设想记入“暂缓的事项”并注明重启条件。
4. **试用反馈的归位路径**：
   - 因人而异的目标与偏好 $\rightarrow$ 写入个人数据仓库的 `settings/`；
   - 跨内容有效的个体辅导假设 $\rightarrow$ 写入个人数据仓库的 `state/traits/`；
   - 适用条件明确、可跨学习者复用的专项经验 $\rightarrow$ 整理为插件 `skills/cairn/references/` 下的学习方法参考；
   - 模型在试用中反复出现的共性偏差 $\rightarrow$ 补充至 `SKILL.md`；
   - 涉及工具或服务端行为的确定性改进 $\rightarrow$ 按第 3 条评估后修改组件层。

| 暂缓多会话通知与全局重整 | 基础版依靠乐观版本校验（`base_version`）和只追加记录处理并发，不引入跨会话实时通知与跨长周期的全局回顾重整机制 | [记忆](design/memory.md) |
| 工具集划分 | 记忆服务提供 14 个工具，按加载、记录、读取、状态维护、设定更新与材料读取分为六组；详细接口参数在实现前写入 `server/SPEC.md` | [服务端](components/server.md) |

### 二、学习模型、提示词机制与记忆精炼化（2026-11-19 至 2026-11-26 讨论确认并整合）

本组决策在交叉对比 Claude 与 ChatGPT 两版方案的基础上，进一步从第一性原理解决了术语自然度、分类僵化、记录与状态重复双写、双链计时脆弱性及跨项目页面可见性问题。

| 议题 | 结论与支撑理由 | 对应文档 |
|---|---|---|
| 核心术语更名（“学习模型”） | 将原译名色彩较重、易误解为多人协作学习的“共同学习模型”统一改为平实的**“学习模型”**；同时清理文档中的口语与比喻词汇（如“冷启动”“脑补”“踩坑”“新陈代谢”“全景”等），统一采用克制的专业书面表述 | [文档总览](README.md)、[学习模型](design/learning-model.md)及各关联文档 |
| 目标的多元形态与不设离散学习分类 | 彻底废弃“讲解型 / 实践型”二分，也不新增固定的“学习意图分类”或“载体类别”。在学习模型顶层“目标”中说明不同范围与深度的收获形态（如建立理解、形成能力、在解决问题中按需学习），明确**目标形态决定达成标准而非绑定教学路径**；同时去掉“默认无提示闭卷完成”的隐性预设，未声明使用条件时参照真实工作环境理解 | [学习模型](design/learning-model.md)、[`SKILL.md`](../skills/cairn/SKILL.md) |
| 以三个跨学科通用条件替代材料/场景分类 | 将不同学习对象与任务的差异提炼为跨学科成立的三个连续判断条件：（1）依据的性质与可核验性（区分材料明文陈述、可客观核验结果与背景/动机/外延推断）；（2）反馈来源与过程可见性（区分有无外部客观反馈、对话内外过程及环境直读能力）；（3）结构复杂度与主次关系（理清核心脉络与次要细节）。不在主模型与通用指引中预设绑定编程、源码或排错的具体场景抓手，保持领域通用性 | [学习模型](design/learning-model.md)、[辅导](design/tutoring.md)、[`SKILL.md`](../skills/cairn/SKILL.md) |
| 面向旗舰模型的提示词写法 | 指引通过清晰的角色定向、目标权衡维度、通用判断条件与系统特有契约来激活旗舰模型的导师模式；去掉覆盖面过窄的局部听课警句（如“听懂的感觉不等于加工发生”），也避免无决策增量的同义反复 | [目标、边界与设计哲学](design/goals-and-principles.md)、[技能](components/skill.md)、[`SKILL.md`](../skills/cairn/SKILL.md) |
| 先推进后收敛与重大分叉协商阈值 | 学习者带着具体问题开始时直接切入回应，不在开场先行盘问目标、分工与大纲；对话内日常教学动作由模型直接选用并调整，仅在遇到显著影响时间投入、学习路线或核心分工的分叉点时说明利弊由学习者拍板；项目设定与大纲在阶段停顿处顺手沉淀 | [学习模型](design/learning-model.md)、[辅导](design/tutoring.md)、[`SKILL.md`](../skills/cairn/SKILL.md) |
| 互动中的假设探测与方式试探 | 将“在推进学习的同时，不打断推进地通过讲解留白、追问切面观察及切换切入方式来校准能力与特征假设”明确为教学判断目标；具体示例放在设计层供维护者参考，不写成死板套路限制模型 | [学习模型](design/learning-model.md)、[辅导](design/tutoring.md)、[`SKILL.md`](../skills/cairn/SKILL.md) |
| 任务要求承接与本地宿主指令边界 | 学习者的自然请求（如“按这份作业要求完成”）即可表达对任务规格的采用，仅在冲突或分工不明时澄清；同时如实写明本地客户端中工作区 `CLAUDE.md` / `AGENTS.md` 具有高于 MCP 工具返回的系统指令优先级，冲突时提示学习者处理 | [辅导](design/tutoring.md)、[插件](components/plugin.md) |
| 四类记忆的价值切分与更新淘汰 | 明确区分 `records/`（按时间只追加的单次过程账本）、`mastery/`（按可复用概念/机制命名的合成最新能力边界，覆盖已被超越的旧快照）、`traits/`（带观察范围、随新表现修订的跨内容辅导假设）与 `progress/`（项目进展概况、客观停留位置及学习者已确定的下一步安排）；状态页与摘要每次更新时主动淘汰过时细节 | [记忆](design/memory.md)、[数据仓库](components/data-repo.md)、[`memory-format.md`](../skills/cairn/references/memory-format.md) |
| 推理归属与按文件严防预设待续事项 | （1）写入记忆时严格区分学习者明确产出的推理/操作与模型顺势补全的环节，后者记作支持条件；（2）针对大模型总结时强倾向生成待办/待续项的问题，在指引中单列总则并按五类文件职责严定边界：`settings/` 仅限学习者确认的规则，`mastery/` 与 `traits/` 纯向后归纳现状（不写“尚待观察/待后续检验”），`progress/` 仅记客观停留位置（含实际发生的中断现象或学习者原问题，不设“未决问题”或“待查问题”）与学习者明确决定的下一步；（3）学习者的决定在其范围、期限与条件内有效，单次安排完成后自然转为历史进度 | [记忆](design/memory.md)、[数据仓库](components/data-repo.md)、[`SKILL.md`](../skills/cairn/SKILL.md)、[`memory-format.md`](../skills/cairn/references/memory-format.md) |
| 彻底剥离双链计时，改读页面 git 历史 | 鉴于依赖模型在 `records/` 中手写 `[[双链]]`（或手动传参）归类相关页面在跨概念交叉时易漏记，且额外维护工具调用日志会破坏纯 git 仓库的可迁移性：决定各状态页的时间信息（首次创建日期、最近更新日期、累计更新天数）直接由服务端从该文件自身的 git 提交历史（含重命名追踪）读取；未整理记录断点检测由服务端直接对比 `records/` 最新时间与 `state/` 最近提交时间得出；`[[双链]]` 纯粹用于页面语义关联召回与 Obsidian 阅读跳转 | [记忆](design/memory.md)、[服务端](components/server.md)、[数据仓库](components/data-repo.md) |
| 全量状态页面名称可见性 | `start_session` 在返回当前关联掌握状态页摘要的同时，返回其余全部状态页面的轻量名称清单（含最近更新日期），打通跨项目先备知识自动识别并防止同义重复建页 | [记忆](design/memory.md)、[服务端](components/server.md) |
| 观察闭环记账、异步推送与双端兼容 | 学习者的决定当场记录，学习表现待局部互动闭环完整或阶段停顿时一并记录与更新状态，避免半途定性并减少网页端远程 MCP 写操作打断；服务端本地同步 `git commit`、后台异步 `git push`，同时兼容网页端插件与本地代理插件 | [记忆](design/memory.md)、[服务端](components/server.md)、[插件](components/plugin.md) |

| 原议题 | 原确认日期 | 原结论要点 | 替代或修订说明 |
|---|---|---|---|
| 学习方法的划分及两份分类方法 | 2026-11-17 | 按“讲解型”和“实践型（分读、写）”划分学习类型，每类配一份方法文件与类型设定 | **全部废弃。** 外在活动名称不决定认知加工与证据范围；改为学习模型下的多元目标形态与三个跨学科通用判断条件，基础版不预置分类方法文件 |
| 设定的三级组织 | 2026-11-16 至 11-17 | 设定分通用、类型、项目三级，类型设定每次加载 | **部分取代。** 取消类型设定，简化为通用设定与项目设定两级 |
| 目标与长期掌握标准 | 2026-11-17 | 统一以“脱离辅助条件下的长期保持与迁移”作为目标内内容的衡量标准 | **取代。** 衡量标准随学习者选定的目标形态（理解、能力、按需解决问题）及真实使用条件而定，也不设“默认无提示闭卷”前提 |
| 记忆按位置决定效力 | 2026-11-15 至 11-17 | 设定整体为指令，记录整体为事实，状态整体为推断；工具结果只提供事实 | **取代。** 改为按决定、自述、观察、推断四种语义解释效力；设定与状态目录保留默认用途，工具结果原样保留各项内容的来源与语义 |
| 页面时间信息由记录双链计算 | 2026-11-17 | 首次记录、最近涉及、涉及天数三项时间由 `records/` 中指向该页面的 `[[双链]]` 算出，并据此提示“被记录涉及但未更新的页面” | **取代。** 双链与计时彻底解耦；页面时间直接取自状态页文件自身的 git 提交历史（首次创建、最近更新、累计更新天数），断点检测改由比对 `records/` 最新时间与 `state/` 最近提交时间实现 |
| `start_session` 隐藏非关联页面名称 | 2026-11-17 | 非当前进度或近期记录链接指向的掌握状态页面仅返回总数量 | **取代。** 改为返回其余全部状态页面的轻量名称清单（含最近更新日期），防止跨项目知识断链与同义页面分裂 |
| 每次写入前拉取、写入后同步推送 | 2026-11-17 | 配置 git 远端时，每次写工具调用均同步等待拉取与推送完成才返回 | **修订。** 本地提交保持同步串行，远端 `git push` 改为后台异步执行，降低对话中的工具等待延迟 |
| 进度页并列记录“学习者决定”与“模型建议” | 2026-11-19（并行初稿） | 进度页固定区分学习者决定与模型提出的后续建议（或候选建议） | **修订。** 去掉预设的“模型候选建议”与泛化的“未决问题”槽位，只保留客观停留位置与学习者明确决定的下一步安排，消除跨对话推测性议程锚定 |

## 暂缓的事项

以下事项不在基础版实现范围内，待相应触发条件出现时启动设计与实现：

| 暂缓事项 | 拟解决的问题 | 重新启动的条件 |
|---|---|---|
| 工作区与终端感知通道扩展 | 让插件通过专门工具或钩子直接采集本地代码变更差异（diff）、编译/测试报错输出与命令执行状态，减少复杂编程与实验任务中的信息搬运损耗 | 基础版跑通后，在本地代理开展编程与排错项目时现有原生读取能力不足以高效捕获过程状态 |
| 本地客户端钩子自动记账兜底 | 在支持 Hooks 的客户端中，利用 `PreCompact` 或会话停止事件自动提醒或由子代理代为整理未落盘的阶段记录 | 基础版实现客户端增强层时，或实际使用中频繁因长对话压缩丢失阶段观察时 |
| 专项学习方法参考库（`references/`） | 针对学术论文精读、超大型代码库走读、实验调优等场景沉淀可复用的结构化切入参考 | 基础版试用中，某类场景反复出现仅靠通用指引难以稳定做好的教学选择问题 |
| 笔记生成与模板模块 | 按自定义模板将阶段梳理导出为结构化学习笔记，管理跨客户端保存与双链组织 | 基础版日常辅导与记忆闭环稳定可用之后 |
| 跨周期全局记忆整理 | 跨越多次对话定期合并碎片页面、清理长期过时或相互矛盾的状态判断 | 状态页面规模增长到阶段性局部更新不足以维持整洁时 |
| 多对话实时变更通知 | 同一时期多窗口并行学习时，向已打开的会话主动提示其他会话刚更新的页面 | 实际使用中出现因并发窗口未重新加载而依据旧状态教学的问题 |
| 已结束项目的主动回顾提醒 | 对已结项且长期未在后续新项目中接触的重要能力提供可选的回顾提示 | 试用中明确产生跨结项项目的定期温习需求 |
| 系统的教学效果评估 | 对辅导前后的长期保持与迁移效果作专门验证 | 积累一定周期的真实使用记录之后 |
