# 议题与决策

本文记录基础版设计的过程与结论状态：修改治理规则、当前有效的确认与整合结论、历史替代关系、暂缓的扩展事项以及下一步计划。系统全貌见[文档总览](README.md)。

## 修改治理规则

基础版设计以 `docs/` 与 `skills/cairn/` 下的当前文档为准，按以下规则演进：

1. **按议题变更**：每次实质设计调整对应明确的议题与理由，通过分支与 PR 提交，同步更新正文与本文的决策状态。
2. **状态效力**：
   - **已确认**：经学习者确认的设计基线，后续实现与细化以其为准；若需推翻或实质修改，须单独说明原因并重新确认。
   - **已被取代的结论**：移入“历史决策与替代说明”，保留演变脉络，不再作为实现依据。
3. **新增机制的准入门槛**：遵循[目标、边界与设计哲学](design/goals-and-principles.md)第 7 条——只有“缺少它基础闭环无法跑通”或“实际使用中已反复暴露对应问题”时才引入新机制，其余设想记入“暂缓的事项”并注明重启条件。
4. **试用反馈的归位路径**：
   - 因人而异的目标与偏好 $\rightarrow$ 写入个人数据仓库的 `settings/`；
   - 跨内容有效的个体辅导假设 $\rightarrow$ 写入个人数据仓库的 `state/traits/`；
   - 适用条件明确、可跨学习者复用的专项经验 $\rightarrow$ 整理为插件 `skills/cairn/references/` 下的学习方法参考；
   - 模型在试用中反复出现的共性偏差 $\rightarrow$ 补充至 `SKILL.md`；
   - 涉及工具或服务端行为的确定性改进 $\rightarrow$ 按第 3 条评估后修改组件层。

### 二、学习模型、提示词机制与记忆精细化（2026-11-19 至 2026-11-28 确认）

本组决策在多轮交叉评审基础上，明确了学习模型术语、多元目标形态、通用判断条件、记忆各部分的职责边界、当前工作状态的接续机制以及 git 时间统计的准确范围。

| 议题 | 结论与支撑理由 | 对应文档 |
|---|---|---|
| 核心术语与平实文风 | 将原译名色彩较重、易误解为多人协作学习的“共同学习模型”统一更名为**“学习模型”**；清理文档中的口语化、比喻性与绝对化措辞，统一使用平实克制的技术文档表述 | [文档总览](README.md)、[学习模型](design/learning-model.md)及各关联文档 |
| 目标的多元形态与不设离散学习分类 | 废弃“讲解型 / 实践型”二分，也不新增固定的“学习意图分类”或“载体类别”。在学习模型顶层“目标”中说明不同范围与深度的收获形态（如建立理解、形成能力、在解决问题中按需学习），明确**目标形态决定达成标准而非绑定教学路径**；去掉“默认无提示闭卷完成”的预设，未声明使用条件时参照真实工作环境理解 | [学习模型](design/learning-model.md)、[`SKILL.md`](../skills/cairn/SKILL.md) |
| 以三个跨学科通用条件替代材料/场景分类 | 将不同学习对象与任务的差异提炼为跨学科成立的三个连续判断条件：（1）依据的性质与可核验性（区分材料明文陈述、可客观核验结果与背景/动机/外延推断）；（2）反馈来源与过程可见性（区分有无外部客观反馈、对话内外过程及环境直读能力）；（3）结构复杂度与主次关系（理清核心脉络与次要细节）。不在主模型与通用指引中预设绑定特定场景的具体抓手 | [学习模型](design/learning-model.md)、[辅导](design/tutoring.md)、[`SKILL.md`](../skills/cairn/SKILL.md) |
| 面向旗舰模型的提示词写法 | 指引通过清晰的角色定位、多元目标形态、通用判断条件与系统特有契约，引导模型从通用助手的单轮答疑转向围绕长期学习目标作教学权衡；不采用覆盖面过窄的局部场景警句，也避免无决策增量的同义反复；`SKILL.md` 只保留通用原则，各目录的具体格式规则收归 `references/memory-format.md` | [目标、边界与设计哲学](design/goals-and-principles.md)、[技能](components/skill.md)、[`SKILL.md`](../skills/cairn/SKILL.md) |
| 先推进后收敛与重大分叉协商阈值 | 学习者带着具体问题开始时直接切入回应，不在开场先行询问全套目标、分工与大纲；对话内日常教学动作由模型直接选用并调整，仅在遇到显著影响时间投入、学习路线或核心分工的分叉点时说明利弊由学习者决定；项目设定与大纲在阶段停顿处整理 | [学习模型](design/learning-model.md)、[辅导](design/tutoring.md)、[`SKILL.md`](../skills/cairn/SKILL.md) |
| 互动中的假设探测与方式试探 | 将“在推进学习的同时，不打断推进地从学习者的提问、预测、解释、取舍和出错反应中获取信号，并在支持受阻时调整切入或呈现方式以验证效果”明确为教学判断目标；具体做法示例仅放在设计层供维护者参考，不在 `SKILL.md` 中列为固定做法清单 | [学习模型](design/learning-model.md)、[辅导](design/tutoring.md)、[`SKILL.md`](../skills/cairn/SKILL.md) |
| 任务要求承接与本地工作区说明冲突 | 学习者的自然请求（如“按这份作业要求完成”）即可表达对任务规格的采用，仅在冲突或分工不明时澄清；本地代理自动加载工作区说明文件（如 `CLAUDE.md`、`AGENTS.md`）且要求与个人设定或请求冲突时，模型直接向学习者说明冲突来源并由学习者决定处理方式 | [辅导](design/tutoring.md)、[插件](components/plugin.md)、[`SKILL.md`](../skills/cairn/SKILL.md) |
| 四类记忆的价值切分与更新淘汰 | 区分 `records/`（按时间只追加的单次过程记录）、`mastery/`（按可复用概念/机制命名的合成最新能力边界，覆盖已被超越的旧快照）、`traits/`（带观察范围、随新表现修订的跨内容辅导假设，基础版维持全文加载并保持精炼）与 `progress/`（项目进展与当前工作状态）；状态页与摘要每次更新时主动淘汰过时细节 | [记忆](design/memory.md)、[数据仓库](components/data-repo.md)、[`memory-format.md`](../skills/cairn/references/memory-format.md) |
| 保留当前分析状态、推理归属与防待办锚定 | （1）写入记忆时严格区分学习者明确产出的推理/操作与模型顺势补全的环节，后者记作支持条件；（2）分开处理“保存价值、陈述方式、行动效力”：允许 `progress/` 保存已尝试结果、注明暂定性质的当前分析判断、正在开展的步骤及学习者要求保留的备忘（区分“决定保存信息”与“决定执行行动”），以降低跨多次对话恢复分析脉络的成本；同时取消“未决问题、待考察事项、候选建议”固定栏目，禁止把未覆盖空白或单方面构想写成待办条目；（3）仅学习者在有效范围与期限内采用的目标、约定和下一步执行决定约束后续安排，其余内容仅供接续参考 | [记忆](design/memory.md)、[`SKILL.md`](../skills/cairn/SKILL.md)、[`memory-format.md`](../skills/cairn/references/memory-format.md) |
| 基于页面内容变更历史的时间信息及其粗筛定位 | 各状态页的时间信息（首次创建日期、最近更新日期、累计更新天数）由服务端从文件 git 提交历史（`--follow`）中统计实际内容变更得出，**排除 `move_page`、`remove_page` 的重命名与双链改写提交**（包含 `write_page`、`edit_page` 及学习者直接修改页面内容的提交）；明确该时间仅作为定位“较久未更新页面”的粗筛线索，具体能力表现间隔以正文所记日期为准；`[[双链]]` 仅用于页面语义关联召回与 Obsidian 跳转 | [记忆](design/memory.md)、[服务端](components/server.md)、[数据仓库](components/data-repo.md) |
| 掌握状态全量名称清单可见性 | `start_session` 在返回当前关联掌握状态页摘要的同时，返回其余全部掌握状态页面的轻量名称清单（含最近更新日期），支持跨项目识别已有概念并防止同义重复建页 | [记忆](design/memory.md)、[服务端](components/server.md) |
| 观察闭环记账、新增记录提示范围与异步推送 | 学习者的决定当场记录，学习表现待局部互动闭环完整或阶段停顿时记录与更新状态（接受半途意外中断且不再继续时丢失未写入轮次细节的取舍）；`start_session` 通过比对 `records/` 条目时间与 `state/` 最近一次由 `write_page` 或 `edit_page` 产生的状态写入提交时间，提供新增记录作为近期变化线索（避免重命名或人工直接编辑推进比较基准而掩盖未整理记录，同时不引入游标对账机制保证检出部分整理中断）；服务端本地同步 `git commit`、后台异步拉取合并与 `git push`，兼容网页端与本地代理插件 | [记忆](design/memory.md)、[服务端](components/server.md)、[插件](components/plugin.md) |

### 三、外部工作流、按需设定组织与跨端目录解耦（2026-11-28 确认）

本组决策明确了跨分散目录与跨客户端的工作流注入机制、`settings/` 的常驻与按需分层演进规则、可选默认材料通道的解耦方式，以及通过本机结构化配置实现跨系统迁移的方案。

| 议题 | 结论与支撑理由 | 对应文档 |
|---|---|---|
| 维持插件加服务端架构与两档部署形态 | 本地学习项目往往分散在不同代码目录中，单目录 `AGENTS.md` 无法跨目录复用，写入用户全局 `AGENTS.md` / `CLAUDE.md` 又会常驻干扰日常非学习的开发工作；采用“插件按需激活 `SKILL.md` + 服务端 `start_session` 送入记忆与设定”既隔离非学习会话，又支持网页端对话模型、可视化控件与本地代理无缝衔接。同一套代码与数据格式按需分“本地轻量模式（`stdio`）”与“远程服务模式（`HTTP`）”两档部署 | [目标、边界与设计哲学](design/goals-and-principles.md)、[插件](components/plugin.md) |
| 默认材料通道解耦与网盘挂载替代 Syncthing | 保留 `list_sources`、`read_source`（含 PDF 书签目录与分页原件截取）、`fetch_materials` 三个工具作为弥补网页端读取大体积 PDF 的可选默认通道；将材料根目录从数据仓库内部解耦为独立可选配置（`SOURCES_DIR` 或 `paths.local.toml` 中的 `roots.materials.path`，远程部署可用 `rclone mount` 挂载 Google Drive 等网盘替代自建 Syncthing）。项目不强制绑定服务端材料目录，新建进度页不再自动创建空材料目录，支持直接读取本地工作区或外部插件 | [服务端](components/server.md)、[数据仓库](components/data-repo.md) |
| `settings/` 常驻边界控制、按需分层与渐进拆分 | 将外部工具协作规则、材料归档约定、个人笔记重点取舍原则与输出模板纳入 `settings/`。严格控制 `settings/general.md` 常驻边界（仅保留高频教学原则与简短入口指针）；`settings/` 下除 `general.md` 与当前 `projects/<项目>.md` 外的其余子目录与页面（如 `workflows/`、`templates/`）在 `start_session` 中统一仅返回相对路径与 `summary`，涉及相关任务时再由 `read_pages` 按需读取全文。初始化不预建空文件，随实际复杂度经学习者确认后由 `update_settings`（支持子目录路径及重命名/删除）拆分为多页并建立引用 | [记忆](design/memory.md)、[服务端](components/server.md)、[`SKILL.md`](../skills/cairn/SKILL.md)、[`memory-format.md`](../skills/cairn/references/memory-format.md) |
| 本机目录索引 `paths.local.toml` 与跨平台可迁移性 | 在数据仓库下引入由 `.gitignore` 忽略的结构化配置文件 `paths.local.toml`（随模板提供 `paths.example.toml`），集中维护逻辑目录名到本机实际路径及 `read` / `read-write` 边界的映射（仅本地 `stdio` 模式返回给客户端，远程 `HTTP` 模式不暴露宿主机路径）。所有纳入 git 的记忆页面仅使用逻辑目录名加相对路径引用外部位置，不硬编码盘符或挂载点，并限定跨工作区写入仅限已授权路径；系统与数据仓库配置 `.gitattributes` 统一文本换行符（`eol=lf`） | [数据仓库](components/data-repo.md)、[服务端](components/server.md)、[辅导](design/tutoring.md) |

## 暂缓的事项

以下事项不在基础版实现范围内，待相应触发条件出现时启动设计与实现：

| 暂缓事项 | 拟解决的问题 | 重新启动的条件 |
|---|---|---|
| 工作区与终端感知通道扩展 | 让插件通过专门工具或钩子直接采集本地代码变更差异（diff）、编译/测试报错输出与命令执行状态，减少复杂编程与实验任务中的信息搬运损耗 | 基础版跑通后，在本地代理开展编程与排错项目时现有原生读取能力不足以捕获过程状态 |
| 本地客户端钩子提醒保存观察 | 在支持 Hooks 的客户端中，利用 `PreCompact` 或会话停止事件自动提醒或由子代理协助整理未落盘的阶段记录 | 基础版实现客户端增强层时，或实际使用中频繁因长对话压缩丢失阶段观察时 |
| 专项学习方法参考库（`references/`） | 针对学术论文精读、大型代码库走读、实验调优等场景沉淀跨学习者可复用的结构化切入参考 | 基础版试用中，某类场景反复出现仅靠通用指引难以稳定做好的教学选择问题 |
| 服务端直连第三方笔记或网盘 API 导出 | 在无本地文件系统的网页端，由服务端直接调用外部笔记软件或云存储 API 写入成稿并维护外部双向链接（注：个人笔记模板与本地授权目录写入已由 `settings/` 按需页和 `paths.local.toml` 支持） | 试用中网页端直接输出 Markdown 成稿或客户端连接器不足以满足归档需求时 |
| 跨周期全局记忆整理 | 跨越多次对话定期合并碎片页面、清理长期过时或相互矛盾的状态判断 | 状态页面规模增长到阶段性局部更新不足以维持整洁时 |
| 多对话实时变更通知 | 同一时期多窗口并行学习时，向已打开的会话主动提示其他会话刚更新的页面 | 实际使用中出现因并发窗口未重新加载而依据旧状态教学的问题 |
| 已结束项目的主动回顾提醒 | 对已结项且长期未在后续新项目中接触的重要能力提供可选的回顾提示 | 试用中明确产生跨结项项目的定期温习需求 |
| 系统的教学效果评估 | 对辅导前后的长期保持与迁移效果作专门验证 | 积累一定周期的真实使用记录之后 |
