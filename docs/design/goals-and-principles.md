# 目标、边界与设计哲学

本文面向 Cairn 的设计者与开发者，说明产品希望取得的结果、责任分配、核心取舍及当前范围。概念关系见[共同学习模型](learning-model.md)，教学依据见[辅导](tutoring.md)，个人信息的延续见[记忆](memory.md)。供辅导模型实际使用的文字另见[指引草稿](../drafts/cairn/SKILL.md)。

## 产品定位与目标

Cairn 是面向个人的 AI 辅助学习系统，以客户端插件提供辅导指引和记忆工具。它把一位学习者的目标、背景、协作约定、进展和表现依据保存为可迁移的个人记忆，使不同对话和模型能够在已有认识上继续学习。

产品的主要投入用于持续理解学习者，以及使这种理解能够被核对、修订和使用。模型负责解释材料与作出教学判断，材料提供知识与任务，Cairn 组织跨次学习需要的个人信息和共同约定。

### 形成学习者重视的能力

辅导服务于学习者希望形成的理解、判断与行动能力。能力要求由使用情境决定：直接回忆、独立执行、查阅资料后分析，或在陌生问题中有效寻求帮助，都可以成为目标。需要长期使用的内容，将保持与变化情境中的运用纳入目标。

学习者可以同时追求任务成果和能力发展，决定哪些部分值得深入承担，以及愿意为之投入多少。模型帮助解释不同分工能提供的学习机会，使任务推进与能力形成之间的取舍清楚可见。目标也可以随着兴趣、处境和对领域的认识变化而调整。

评价辅导时，既关注能力表现，也关注取得这些进展所需的时间、负担和学习体验。具体判断使用[共同学习模型](learning-model.md)中对目标条件、实际支持与表现证据的区分。

### 保持可迁移的学习连续性

记忆由学习者拥有，以可阅读文本保存在其数据仓库中。跨对话与跨模型延续所需的信息包括当前目标、实际工作位置、已有判断的依据与范围，以及接续安排。

连续性包含承接与修订两方面。后续模型能够沿用仍适用的认识和安排，也能够根据新目标或新表现更新它们。准确记录有条件的判断，比保存脱离条件的能力标签更有助于这种延续。来源、范围与效力的具体要求见[记忆](memory.md)。

### 使个人安排与系统能力能够演进

个人目标与协作约定通过设定调整，教学认识通过状态与记录积累，通用指引和技术组件通过系统更新改进。不同内容分别维护，使学习者更换客户端或升级插件时，仍然保有自己的数据和选择。

基础版先提供完整的辅导与记忆使用过程。实际使用帮助判断哪些教学内容值得独立整理，哪些确定性工作值得交给系统，以及新增能力是否足以抵偿维护成本。

## 产品价值的检验

设计评审检查文字、职责与接口能否支持预期行为；试用进一步观察这些安排能否带来学习价值。二者使用不同范围的证据。下面的标准用于产品核对，具体学习活动由学习者目标与教学选择决定。

| 产品目标 | 可直接检查的表现 | 解释条件 |
|---|---|---|
| 能力发展 | 在目标相关的后续任务中，出现原先尚不能完成的解释、判断或行动，或完成得更加可靠 | 对照任务要求、学习者实际贡献和所获支持；目标涉及保持或迁移时采用相应时间与情境 |
| 学习连续性 | 更换客户端或模型后，新对话凭记忆准确说明当前目标、实际进展和接续安排，并继续工作 | 检查摘要与正文是否保留必要条件，既往判断是否被正确使用 |
| 决定权与投入 | 学习者改变目标、分工或约定后，相关安排随之更新；能够理解重要安排的用途并决定投入 | 结合明确选择、适用范围、学习者反馈和实际负担 |
| 可核对与可修订 | 学习者能够读懂一项判断的依据，指出误记或遗漏；新信息能进入当前状态 | 区分历史记录与当前判断，检查更正及相关状态是否一致 |
| 可迁移与可演进 | 个人设定可调整，数据能在支持相同约定的客户端使用，组件更新保留个人内容 | 依据实际加载、修改、接续结果及相应接口约定 |

任务成果和对话体验能够提供有用反馈，关于持久能力的结论则使用相应范围的表现。基础版通过已有互动、记忆与学习者反馈取得这些信息，专门的效果评估功能按后续需要考虑。

## 设计哲学

### 学习者决定目标，模型承担教学判断

学习者决定方向、投入、任务分工及持续协作约定。这是产品对个人自主性的承诺。模型协助形成目标、解释取舍，并在已有目标和约定内自主选择讲解、示范、提问、反馈及局部尝试。

决定的效力与范围相联系。一次性安排完成后成为进度，项目约定在该项目及其条件内适用，持续约定由学习者修改或随其条件结束而终止。模型自己的教学安排可以在后续学习中调整，已经开展的工作与选定的接续步骤仍需如实保存。

这种责任分配使模型能够直接处理日常教学选择，也使方向和显著投入的变化仍由学习者掌握。对能力和方法效果的认识则依据表现修订，确认一项安排与认同一项判断分别解释。

### 教学知识说明条件、关系和理由

共同学习模型定义目标、活动、支持与证据怎样关联，教学依据说明哪些安排为什么有助于学习。文档把研究结果、理论解释与 Cairn 的设计采用分别说明，使维护者能够判断主张的适用范围，并在新证据出现时修订。

模型指引保留行动需要的完整判断依据。设计文档进一步展开概念、研究来源、取舍理由和适用边界，供设计者与开发者理解为何这样组织。两者的详略由读者与用途决定，指引通过必要的参考文件取得格式等操作细节。

指引和设计正文使用专业、平实的完整句子，陈述目标、条件和关系。示例在能够澄清边界或显著提高理解效率时采用，并保留其具体语境。否定性行为条目用于实际使用中反复出现的问题，或由当前系统能力决定的不可行做法；编写约定集中在[技能](../components/skill.md)中。

### 个人记忆既能延续认识，也能接受修订

个人信息以便于学习者阅读和编辑的文本保存。观察、能力判断、背景自述和实际决定各自保留来源及范围，使不同模型能够理解同一条记忆所表达的含义。

记忆的详细程度取决于后续使用价值。当前判断可以概括多次观察，相关记录保留必要依据；已有证据支持的有限认识可以独立成立。是否取得更多表现由教学活动的价值与投入决定，具体规则见[教学选择](tutoring.md#教学选择)。

当前约定、当前状态与历史事件各有保存位置。内容的组织支持查找和更新，实际效力由内容含义及学习者选择确定。模型写入、概括和读取时维持这种关系，学习者可以据此核对和纠正。

### 教学判断与确定性工作分别承担

内容理解、活动选择、表现解释和个人信息的概括由模型负责。时间计算、索引生成、链接维护、存取、同步及版本校验由系统承担。确定性工作集中实现，能够减少重复操作，也使系统所保证的行为清楚可查。

技能、记忆服务和数据仓库通过工具接口、记忆格式及内容效力的约定衔接。组件可以分别改进，接口与格式变化则说明对已有数据和调用方式的影响。服务端保证能够机械检查的读写行为，内容的理解和判断保留可供人核对的依据。

### 按实际需要控制规模

基础版优先完成加载记忆、开展辅导、保存进展和跨次接续所需的工作。一项新机制进入基础版，需要解决基本过程中的必要问题，或针对实际使用已经呈现的问题；其他构想保留用途与重新考虑的条件。

通用教学依据与具体教学做法可以直接进入指引。当前版本先交付完整指引和记忆格式参考，专项方法根据教学需要、复用价值及维护成本再整理。适用于某个学习者的选择进入其设定，方法效果作为有条件的认识保存，可跨情境复用的内容再考虑归入系统。

概念与规则的保留需要能够说明实际作用：删除它会使哪项判断、责任区分或设计取舍失去必要依据。承担运行职责的内容落实到指引、格式或工具说明；解释研究和取舍的内容保留在设计层。段落删减以是否损失必要信息为准，完整性和可用性通过正文与具体场景共同检查。

## 核心边界与当前范围

以下边界明确核心系统的维护责任。学习者仍可在各自项目中选择适合的安排。

| 核心不采用的做法 | 采用的设计与范围 |
|---|---|
| 统一的学习流程与掌握门槛 | 以目标、活动、支持和证据指导判断；学习者可以选择课程流程或阶段要求 |
| 通用学科知识库 | 使用学习材料与模型可获得的知识，系统集中维护个人学习与连续性 |
| 单一数值表示掌握状态 | 用文字描述能力、条件与依据；实际成绩、耗时和错误数量可以作为表现数据 |
| 系统强制执行的复习任务表 | 时间信息支持教学判断，已经选择的计划用于接续；活动按其价值与投入安排 |
| 对判断正确性的机器证明体系 | 以文本、链接和修改历史支持人的核对，服务端保证确定性的存取规则 |

基础版服务于一位学习者自己的数据仓库，支持本地安装与服务器部署。材料可以围绕课程、书籍、代码库或其他项目组织，领域教学内容按需要积累。技能与 MCP 提供跨客户端的共同基础，增强能力依据客户端实际支持提供。

记忆维护采用学习过程中的记录、阶段性状态更新和再次读取。跨多次对话的整体整理、变更通知、笔记生成、主动提醒和专门效果评估功能，属于有明确重新考虑条件的扩展事项，见[议题与决策](../decisions.md)。

基础版目前为设计方案，现行 v1 的行为仍由根目录 [DESIGN.md](../../DESIGN.md) 和 [server/SPEC.md](../../server/SPEC.md)说明。设计文本、模型正文草稿、工具详细规格和实现进展分别记录在[文档总览](../README.md)与[议题与决策](../decisions.md)中。
