# 目标、边界与设计哲学

本文说明 Cairn 基础版要达到的目标、有意不做的事、当前版本的限制，以及设计中出现取舍时依据的立场。它是设计层的第一份文档：共同的概念见[共同学习模型](learning-model.md)，教学依据和教学安排见[辅导](tutoring.md)，记忆的语义与组织见[记忆](memory.md)。各项内容的确认状态见[议题与决策](../decisions.md)。

## 三个层次

设计中的规范性陈述分为三个层次。它们回答的问题、面向的对象和写入的位置各不相同。

| 层次 | 回答的问题 | 面向的对象 | 所在的位置 |
|---|---|---|---|
| 产品目标 | 系统要为学习者达到什么结果，怎样检验 | 使用者、贡献者 | 本文 |
| 设计哲学 | 设计中出现取舍时依据什么立场 | 设计者、贡献者 | 本文 |
| 教学依据 | 学习在什么条件下发生，辅导据此怎样安排 | 模型（经由指引）；研究依据和设计推论面向设计者 | [辅导](tutoring.md)；指引正文 |

三个层次共用[共同学习模型](learning-model.md)定义的概念，包括目标能力、使用条件、学习状态、活动与支持、表现与证据。

三者的关系如下：
- 产品目标限定系统的范围。
- 设计哲学决定为实现目标而作出的各项选择，其中包括指引的写法。
- 教学依据由学习科学的研究推出，是指引的主要内容，写法受设计哲学约束。

总体结构、记忆格式、工具和插件实现是这些内容的具体化，不另成一个规范层次。

区分层次有两方面的作用。
- **各层次写入不同的位置。** 设计哲学不写入指引，因为模型在辅导时不需要了解设计立场；教学依据不列为设计哲学，因为它说明的是学习的规律，而不是设计取舍的理由。
- **各层次的修改依据不同。** 产品目标随使用者的需要调整，设计哲学随设计经验调整，教学依据随研究进展和使用中的观察调整。

## 产品目标

Cairn 是面向个人的 AI 辅助学习系统，以客户端插件的形式提供。系统的目标有三项。

**学习记忆归学习者所有，可以跨客户端和模型延续。** 与学习有关的记忆集中保存在学习者自己的数据仓库中，采用纯文本格式，不依赖特定的客户端或模型。记忆包括：
- 学习者的目标、背景和约定；
- 学习进度；
- 对能力的判断及其依据；
- 学习记录。

更换客户端或模型后，学习可以从原有状态继续。此前的判断连同依据一起延续：之后的模型可以在其基础上教学，也可以依据新的表现修订它。

**辅导促进学习者目标能力的形成。** 辅导服务于学习者的目标：希望形成什么能力，在什么条件下使用，需要保持多久，都由学习者决定（见[共同学习模型](learning-model.md)）。模型依据目标、学习者当前的状态和表现安排教学。对需要长期使用的能力，辅导关注它在间隔之后、在新的情境中能否发挥作用。辅导同时考虑学习者的时间和负担：学习者理解每项安排的用途，并决定自己的投入。

**随使用演进。** 学习者通过设定表达目标、偏好和对辅导方式的约定，修改设定即可改变之后的辅导。模型在辅导中识别对该学习者有效的方式，可以建议把其中稳定的部分写入设定。系统的各组成部分可以独立升级，升级不影响已有的记忆。

### 检验的标准

每项目标对应可以直接检查的表现。前四项检验系统是否按设计工作，在一次或几次使用中即可检查。最后一项检验学习效果，需要与目标相符的任务和观察周期，不能凭一次表现良好的对话判断。

| 检查的内容 | 可以直接检查的表现 |
|---|---|
| 跨对话、跨模型延续 | 新的对话仅凭已有记忆，就能准确说明学习者当前的目标、实际进展和接续安排，并继续学习，不需要学习者重新介绍；任一页面都可以用普通的文本编辑器阅读 |
| 判断与依据相符 | 对同一项任务的结果，记忆区分学习者完成的部分和得到的支持，能力判断的范围与依据相符 |
| 学习者的决定得到执行 | 学习者调整目标或约定后，之后的辅导按新的决定进行，不需要修改插件；模型提出的建议在之后的对话中仍然是建议 |
| 记忆的修订 | 已有的判断为新的对话提供起点，并在出现相关的新表现时得到修订；插件升级后，原有的记忆无需手工调整即可继续使用 |
| 目标能力的形成 | 在与目标相符的任务和资源条件下，学习者的表现随学习而发展；间隔之后，需要长期保持的内容仍能运用 |

## 边界

边界分为两类：
- **长期的产品取舍**：有意不采用的常见做法，属于设计选择，不随版本改变。重新讨论时，需要说明当初的理由为什么不再成立。
- **当前版本的限制**：由现阶段的范围决定，会在后续版本中逐步解除。

### 有意不采用的常见做法

| 不采用的做法 | 原因 | 本系统的做法 |
|---|---|---|
| 系统统一的教学流程和掌握门槛：按预设的步骤推进，达到阈值后进入下一单元 | 预设的流程和阈值难以适应不同的学习者、目标和内容；旗舰模型依据目标和学习状态作出的判断更贴合具体情境 | 指引说明目标、教学依据和判断方式，由模型安排；学习者可以自行设定课程计划、阶段要求或完成标准，它们作为学习者的决定执行 |
| 维护通用的学科知识库：知识图谱、题库、针对教材的检索增强 | 学科知识已包含在模型和学习材料中，另行维护的成本高且容易过时；系统特有的价值在于对学习者的了解 | 记忆只保存与学习者有关的信息；学习材料原样提供给模型阅读和检索 |
| 以单一数值表示掌握程度：百分比、等级分 | 数值没有可以核对的含义，容易被当作精确的结论，不同模型给出的数值也不可比 | 掌握以文字描述：在什么条件下完成了什么，依据是什么；测验成绩、用时等实际数据可以作为表现记录 |
| 由系统生成并强制执行的复习任务 | 固定的排期与当前的学习脱节，并使检验与学习活动分离 | 服务端提供时间信息，模型结合目标和当前的学习安排回忆与再次运用；学习者可以自行选择复习计划 |
| 对判断正确性的机器证明体系：结构化的证据链，由服务端校验 | 维护成本高，约束集中于记录而不是教学 | 人可核对：纯文本，判断写明依据和条件，学习记录只追加，git 保留修改历史 |

### 当前版本的限制

- **一位学习者。** 一个数据仓库对应一位学习者。多人使用时，各自安装插件、各自建立数据仓库；账号体系和托管服务不在当前范围内。
- **不预置学习方法。** 辅导依据指引中的教学依据进行；可以复用的方法，在使用中出现反复的选择问题时再加入（见[辅导](tutoring.md)）。指引中的示例面向计算机科学与 AI 基础设施方向。
- **不包含扩展模块。** 笔记生成、跨对话的记忆整理和教学效果评估都不在基础版中。
- **项目结束后不主动回顾。** 学习项目结束后，其中没有被之后的学习再次涉及的内容，系统不会主动提出回顾；学习者可以随时要求。
- **对话之间不通知。** 多个对话同时进行时，写入不会相互覆盖；但一个对话在重新加载记忆之前，不会得知其他对话所作的更新（见[记忆](memory.md)）。
- **指引以中文撰写。**
- **依赖客户端的支持。** 系统依赖客户端对技能和 MCP 的支持；命令、钩子和子代理等增强功能只在部分客户端生效（见[插件](../components/plugin.md)）。

## 设计哲学

设计哲学是设计中出现取舍时依据的立场，共七条。每一条先陈述立场，再说明理由和它在设计中的含义。

**1. 模型为主、目标导向。** 系统面向旗舰模型设计。指引陈述目标、共同的概念、教学依据和模型可以使用的信息，具体做法由模型依据情境判断；不规定教学流程，也不针对不同水平的学习者预设处理方式。

否定性的规定只在两种情况下写入：一是实际使用中反复出现的不当做法，二是由当前系统的限制决定的不可行做法。写入时说明它所针对的现象。

理由是模型的能力在持续提高，固定的流程和预防性的细则带来的收益随之下降，并且妨碍模型依据具体情境作出判断。一种倾向是否需要约束，以实际使用中的观察为准。

**2. 有理论依据。** 教学依据由学习科学中证据较为充分的结论推出。每一条说明学习在什么条件下发生、对教学有什么含义，使模型能够在依据没有覆盖的情形下自行推理。

设计文档区分三类内容：研究支持的结论，由此作出的设计推论，以及使用中得到的观察。引用研究时保留它的条件和限度。系统机制在引入时须说明它要解决的问题及其依据，不能说明的机制不引入。

**3. 个人的内容归入记忆，可以复用的内容归入插件。**
- **记忆中：** 学习者的目标、背景、偏好和对辅导方式的约定，保存在学习者的记忆中，不写入插件。
- **插件中：** 不针对某一位学习者的内容，包括指引、教学依据，以及写明了适用条件、可以在不同学习者之间复用的方法。
- **优先关系：** 学习者的决定优先于插件中的做法。

这样，学习者调整辅导时不需要修改插件，插件升级也不会覆盖学习者的设定。

**4. 确定性的工作由系统承担。** 能够由服务端或插件确定完成的事项不交给模型，包括：
- 时间的记录与计算；
- 链接解析与索引生成；
- 同步与版本校验；
- 写入规则的保证。

引入一项机制时，优先选择不需要模型额外配合的实现方式。理由是模型的注意力应当用于理解内容和作出教学判断；需要模型逐步配合的机制会增加指引的长度，而且在长对话中执行不稳定。

同样的道理，系统不依赖无法可靠得知的事件。对话何时结束，服务端和模型都无法确定，因此任何步骤都不以对话结束为前提。

**5. 组成部分通过稳定的约定衔接。** 指引、记忆服务和记忆三个部分，通过工具接口、记忆格式和内容的语义三项约定衔接，各自可以独立修改和替换（见[文档总览](../README.md)）。新增的功能以扩展模块的形式加入，不修改基础部分。记忆格式是各部分之间最稳定的约定，它的变更需要版本号和迁移说明。

**6. 人可核对。** 记忆以纯文本保存，学习者可以直接阅读和编辑。核对依靠以下安排：
- 每项判断写明依据、条件和时间；
- 学习记录只追加，更正以新的条目追加；
- git 保留全部修改历史。

学习者据此可以核对任何一项判断的来源，修订不准确或已经过时的内容。系统不要求服务端对判断的正确性作形式化校验。

**7. 依据实际使用演进。** 基础版只包含进行学习、并在历次对话之间保持学习状态所必需的部分。一项机制只在两种情况下加入：
- 缺少它时，基础流程（加载记忆、辅导、更新记忆）无法完成；
- 实际使用中已经出现它要解决的问题。

其余的想法登记为暂缓的事项，写明重新考虑的条件（见[议题与决策](../decisions.md)）。学习方法同样如此：插件不预置方法，使用中出现反复的选择问题时再加入。
