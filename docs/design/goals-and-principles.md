# 目标、边界与设计哲学

本文面向 Cairn 的设计者、开发者与维护者，说明基础版要实现的产品目标、可检查的验收标准、产品边界与当前范围，以及设计取舍所依据的立场。共享的学习概念见[学习模型](learning-model.md)，教学依据与辅导安排见[辅导](tutoring.md)，记忆的语义与更新机制见[记忆](memory.md)。各项决策的状态见[议题与决策](../decisions.md)。

## 三个规范层次

系统中的规范性陈述按职责分为三个层次，分别面向不同对象、存放在不同位置。

| 层次 | 回答的问题 | 面向的对象 | 所在位置 |
|---|---|---|---|
| 产品目标 | 系统要为学习者带来什么结果，如何检验 | 使用者、维护者 | 本文 |
| 设计哲学 | 设计出现取舍时依据什么立场，如何划分人与模型及服务端职责 | 设计者、开发者 | 本文 |
| 教学依据 | 学习在什么条件下发生，辅导判断据此关注哪些关系 | 维护者（含研究出处与限度）；模型（经由指引正文） | [辅导](tutoring.md)；[`SKILL.md`](../../skills/cairn/SKILL.md) |

三个层次共享[学习模型](learning-model.md)定义的概念：
- 产品目标界定系统服务的学习结果与连续性承诺；
- 设计哲学决定系统架构、组件边界以及指引提示词的编写方式；
- 教学依据提供影响模型日常教学权衡的原理支撑，其面向模型的表达方式受设计哲学约束。

分离这三个层次有两个直接用途：一是避免把面向开发者的设计理由和架构防线塞入给模型的运行时提示词；二是明确不同内容的修改条件——产品目标随使用者需求调整，设计哲学随工程经验修正，教学依据随研究证据与实际辅导观察迭代。

## 产品目标

Cairn 是以客户端插件形式提供的个人 AI 辅助学习系统，核心目标有三项。

**1. 集中维护归学习者所有、可跨平台迁移的长期记忆。**  
与个人学习有关的信息以纯文本保存在学习者自己的 git 数据仓库中，不绑定单一客户端或模型厂商。记忆涵盖学习者的背景自述、目标与协作约定、项目进度现场、领域掌握状态、跨内容学习特征以及按日期归档的学习记录。更换客户端（如在网页聊天界面与本地编码代理之间切换）或更换底层模型后，新的对话可以在已有认识与工作现场上直接继续，并依据新表现修订旧判断。

**2. 围绕学习者的多元目标提供自适应辅导。**  
学什么、希望收获什么形态的结果（建立结构性理解、形成特定条件下的运用能力，或在解决眼前问题时按需补足认识）、愿意投入多少时间，均由学习者决定。模型在日常互动中结合目标条件、先备知识与即时反应调整讲解、示范、提问和尝试的比重，以低打断的方式校准对学习者状态与特征的假设，兼顾能力进展与推进节奏。

**3. 支持个人辅导方式与系统组件随使用演进。**  
学习者可以通过设定随时调整目标和协作约定；模型在多次互动中观察到对该学习者稳定有效的切入方式或常见盲区时，可将其沉淀为学习特征假设，或在确认后写入设定。系统的指引、服务端与存储模板通过稳定接口解耦，升级插件或服务端不破坏已积累的个人记忆。

### 检验标准

每项目标对应可直接核查的表现。前四项检验系统机制与提示词是否按设计运行，可在单次或数次跨会话使用中核验；最后一项检验实际教学成效，需要结合具体目标的观察周期评判。

| 检验维度 | 可直接核查的表现 |
|---|---|
| 跨对话与跨客户端延续 | 切换客户端或新开对话后，模型仅凭 `start_session` 加载的记忆即可准确把握当前目标、停留现场与相关先备知识并直接推进，无需学习者重新交代背景；所有记忆文件均可直接用文本编辑器或 Obsidian 阅读 |
| 表现归属与判断范围 | 对同一项任务成果，记录与掌握状态能如实区分“学习者独立说出的推理或完成的操作”与“模型提示或顺势补全的部分”，判断范围不超出实际观察条件 |
| 决定权与防预设干扰 | 学习者修改目标或约定后，后续辅导按新决定执行；开场提问能直接进入内容而不被建档流程阻断；未经采纳的旧建议不会写入进度页支配后续对话 |
| 状态的更新与版本兼容 | 已有判断能为新项目提供跨项目先备知识参考，并在出现新表现时覆盖过时快照、淘汰冗余细节；插件升级后既有数据仓库可直接使用 |
| 目标结果的达成 | 在与学习目标相符的情境和资源条件下，学习者对目标机制的解释、分析或独立处理能力随学习推进出现可观察的改善；需要保持的内容在间隔后仍能调用 |

## 边界与当前范围

系统边界区分为两类：**长期产品取舍**是核心定位决定的非目标，不随版本推进改变；**当前版本范围**是基础版为控制初期复杂度所作的阶段性收敛，后续可按实际需求扩展。

### 有意不采用的常见做法

| 不采用的做法 | 原因 | 本系统的做法 |
|---|---|---|
| 系统预设的固定教学流程与过关门槛 | 刚性步骤与统一及格线无法适应不同的目标形态、材料结构和先备基础，也会限制旗舰模型的实时判断 | 指引提供角色定位、权衡维度与判断条件，由模型结合实时表现决策；学习者若自定阶段标准，作为个人决定执行 |
| 维护通用学科知识库或题库 | 学科知识已在模型权重与学习材料中，单独维护知识图谱成本高且易过时；Cairn 的独特价值在于“对这位学习者的长期了解” | 记忆只保存与学习者个人有关的信息；原始教材、论文与代码放在 `sources/` 或本地工作区按需读取 |
| 用单一数值或百分比表示掌握度 | 分数缺乏可核对的具体含义，且跨模型、跨任务不可比，还会掩盖支持条件的差异 | 用带条件的自然语言描述能做什么、依据哪次表现及得到了何种支持；客观测试得分或耗时可作为表现事实记录 |
| 由系统自动排期并强制推送的复习任务表 | 脱离当前学习主线的机械复习排期容易打断进行中的项目，把检验与真实运用割裂开 | 服务端提供各状态页基于 git 历史的更新与间隔信息，模型仅在与当前目标相关且具学习价值时自然引入回顾 |
| 面向机器形式化审计的证据链校验 | 复杂的证据编号对账和状态机锁会大幅推高提示词与工具负担，使记账压过教学本身 | 采用“人可核对”原则：纯文本存储，判断写明日期与条件，学习记录只追加，git 完整保留历史变更 |

### 当前版本的范围与限制

- **单用户个人仓库**：一个数据仓库服务于一位学习者；多人使用各自独立部署，不包含多租户账户体系。
- **跨平台基线与环境感知通道的边界**：基础版以“技能 + MCP 工具”为跨客户端共同基线，同时兼容网页端（ChatGPT、Claude 网页/移动应用）和本地编码代理（Claude Code、Codex）。在环境感知上，基础版仅通过对话内容与 `sources/` 静态材料工具获取信息（本地代理可额外使用宿主自带的文件读取能力）；**专门采集工作区代码 diff、终端报错日志或测试运行输出的工具适配不在基础版范围内**，留作后续感知通道扩展，上层学习模型与记忆结构对此保持中立。
- **不预置独立的专项学习方法文件**：通用的目标权衡、材料判断条件和教学依据直接内聚在指引正文中；针对论文精读、特定领域调优等深度专项方法，待试用中出现明确复用需求后再以参考文件（`references/`）扩展。
- **不包含扩展模块**：按模板导出整理笔记、跨长周期的全局记忆重整、独立的教学效果评估模块均列为暂缓事项。
- **已结束项目不主动触发提醒**：项目结束后，未在后续新项目中关联到的旧内容，系统不主动发起复习提醒；学习者可随时指定回顾。
- **并发对话间无实时推送**：多窗口同时学习时，写入规则保证文件不互相覆盖，但一个对话在重新调用读取工具前不会自动获知另一对话刚写入的变更。

## 设计哲学

设计出现取舍时遵循以下七条立场。

**1. 模型为主，以目标与权衡维度激活判断。**  
系统面向旗舰模型设计。模型的预训练分布中已包含丰富的教学与领域分析能力，但通用助手的后训练先验使其默认倾向于“单轮把答案讲满、顺从表面请求、快速完结任务”。指引的作用不是用死板步骤或离散分类绑住模型，也不是堆砌局部场景的窄面警句，而是**通过清晰的角色定向、多元目标形态和关键权衡维度激活导师模式**，把实时教学选择留给模型。

否定性行为限制仅在两种情况下写入指引：一是实际使用中反复观察到的偏差，二是由当前系统架构决定的客观限制。

**2. 教学设计建立在有边界的理论依据之上。**  
教学依据提炼自认知与教育心理学中证据较充分的研究。设计文档严格区分三件事：原研究在特定实验条件下支持的结论、Cairn 据此作出的教学设计推论、以及个人使用中的经验观察。引用研究时保留其任务背景与局限，避免把局部实验现象夸大为无条件定律。

**3. 个人信息归数据仓库，通用知识归系统插件。**  
凡是因人而异的目标、背景、协作约定、状态判断和记录，全部保存在学习者私有的数据仓库中；凡是不针对特定个人、可跨学习者复用的指引、格式规范与工具逻辑，全部保存在公开的系统仓库中。个人设定与插件默认做法不一致时，以学习者的决定为准。插件升级与个人数据互不污染。

**4. 确定性工作由系统承担，减少模型的维护负担。**  
时间记录、基于 git 历史的页面时间统计、双链解析、全量页面索引生成、并发版本校验以及本地提交与后台异步推送，均由服务端确定性完成。系统机制的设计避免依赖模型在长对话中逐步维持脆弱的文本约定（例如不依赖模型在记录中手写双链来计算复习间隔，也不依赖无法可靠捕获的“对话结束”事件）。

**5. 组件之间通过最小稳定契约解耦。**  
指引、记忆服务与数据仓库仅通过工具接口、记忆格式和内容语义三项约定连接。未来扩展本地钩子兜底、新增工作区报错感知工具或增加专项参考文件时，只需在对应组件层增量接入，无需推翻核心模型与既有数据格式；数据格式确需变更时，通过 `FORMAT_VERSION` 与迁移脚本管理。

**6. 人可核对、可编辑、可回溯。**  
记忆采用与 Obsidian 兼容的 Markdown 纯文本格式：学习记录按日期只追加，错误通过追加更正条目说明；掌握状态与学习特征在合成更新时保留关键依据的日期与支持条件；每次写入对应清晰的 git 提交。学习者随时可以直接打开目录阅读、核对或手动修改任何页面。

**7. 依据真实使用演进，克制预设复杂度。**  
基础版只保留跑通“加载记忆—开展辅导—阶段更新—跨次接续”闭环所必需的要素。新增机制或独立方法文件需满足两个条件之一：缺少它会导致基础闭环无法成立，或实际使用中已反复出现它要解决的具体问题。其余设想统一登记在[议题与决策](../decisions.md)的暂缓列表中，注明重新启动的条件。
