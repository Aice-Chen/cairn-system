# 目标、边界与设计哲学

本文说明 Cairn 基础版的产品定位、预期结果、设计取舍和范围。学习目标、学习状态、活动、支持与证据之间的关系由[共同学习模型](learning-model.md)定义；模型如何据此辅导见[辅导](tutoring.md)，个人信息如何组织见[记忆](memory.md)。设计的确认状态与后续工作见[议题与决策](../decisions.md)。

## 产品定位与文档职责

Cairn 是面向个人的 AI 辅助学习系统，以客户端插件的形式提供。它将学习者的目标、背景、约定、学习进展和表现依据集中保存，并向模型提供辅导指引与读写记忆的工具，使多次对话能够围绕同一位学习者的需要持续开展。

系统特有的价值在于保持对学习者的连续了解。学习材料提供内容，模型承担解释、推理和教学判断，Cairn 使这些判断能够参考既往学习，并把本次获得的认识交给后续对话。学习者拥有这些记忆，可以核对、修订和迁移它们。

产品设计、共同学习模型、辅导指引与实现承担不同职责。

| 内容 | 回答的问题 | 所在文档 |
|---|---|---|
| 产品目标 | 系统希望为学习者带来什么结果，如何判断它的价值 | 本文 |
| 设计哲学 | 为达到目标，系统如何分配责任、保留自主性并控制复杂度 | 本文 |
| 共同学习模型 | 目标、状态、任务、活动、支持、证据和记忆分别表示什么，如何关联 | [共同学习模型](learning-model.md) |
| 辅导原则与方法 | 模型根据哪些依据选择教学做法，如何观察与调整 | [辅导](tutoring.md) |
| 结构与实现 | 指引、记忆服务和数据仓库如何提供所需能力 | [技能](../components/skill.md)、[服务端](../components/server.md)、[数据仓库](../components/data-repo.md)、[插件](../components/plugin.md) |

目标说明预期的结果，共同学习模型提供描述和判断的概念，设计哲学决定系统的责任划分，辅导原则将这些内容用于学习互动。接口、文件格式和工具是对应的实现约定。各层保持明确的引用关系，使教学模型可以调整，且调整的影响能够被准确追踪。

## 产品目标

### 学习记忆由学习者拥有，并能够跨模型延续

与个人学习有关的信息集中保存在学习者自己的数据仓库中，采用可直接阅读的文本格式。学习者更换客户端或模型时，原有目标、进度、约定和表现依据仍可供下一次辅导使用，减少反复介绍背景和重新定位学习起点的负担。

可迁移的内容包括已有判断及其依据。后续模型据此了解哪些表现已经观察到、发生于什么条件、哪些部分仍需确认，并结合当前表现作出新的判断。连续性体现在能够承接学习，也体现在能够修订此前的认识。

### 辅导促进目标能力的形成

辅导服务于学习者希望形成的目标能力。能力需要达到的程度结合任务与使用条件确定：有些内容需要能够直接提取或独立执行，有些内容需要能够借助资料和工具完成分析，还有些内容需要能够进入陌生问题、识别缺口并继续学习。具体概念和关系见[共同学习模型](learning-model.md)。

对需要长期使用的能力，产品关注其保持、迁移与继续发展的情况。即时任务中的表现提供当前依据，后续情境中的表现进一步说明能力是否稳定、适用范围有多大。学习与即时表现的区分有学习科学研究支持；将这种区分用于持续辅导和记忆，是 Cairn 的设计选择（Soderstrom & Bjork, 2015）。

自主能力也可以包含对资源的有效使用。学习者能够判断需要什么信息，使用资料、工具或他人的帮助，并对结果进行核验，是许多真实任务的一部分。“为未来学习做好准备”的迁移观强调这种在新环境中继续学习的能力（Bransford & Schwartz, 1999）。Cairn 因而根据目标说明哪些判断与行动需要由学习者承担，哪些资源属于完成任务的正常使用条件。

目标可以从兴趣、现实问题或课程要求逐步形成。模型帮助学习者看清可能的方向、所需能力和投入，再由学习者确定取舍。随着对领域的理解加深，或时间与需要发生变化，目标可以调整。形成目标和调整目标都是辅导的一部分，其具体关系见[共同学习模型](learning-model.md)。

### 辅导方式和系统能够随使用演进

学习者通过设定表达背景、目标、偏好与持续适用的约定。模型利用这些信息安排辅导，并记录实际表现与教学反应。适合持续保留的个人安排可以由模型提出，经学习者确认后成为设定；关于某种做法是否有效的判断则继续保留其适用条件和依据。

产品价值同时涉及学习结果与投入。模型应结合可用时间、任务期限和学习体验选择安排，使学习者能够理解安排的用途，并对投入、分工和进度作出决定。有效的个性化辅导需要既促进能力发展，也保持学习者能够持续参与的负担水平。

系统的指引、记忆服务和记忆保持清晰边界。个人安排能够通过设定调整，通用教学知识能够修订，技术组件能够单独升级。每种调整按照其影响范围进行，使系统在使用中逐步完善。

## 如何判断产品的价值

判断 Cairn 的价值，需要同时观察学习者的变化、学习过程和系统的连续性。以下标准用于设计取舍和试用中的核对，基础版通过已有的学习互动、记忆和学习者反馈获取相关信息。

| 观察方面 | 值得关注的变化 | 判断时需要结合的条件 |
|---|---|---|
| 目标能力 | 学习者能够完成原先不能完成的解释、判断或行动；在相关任务中的表现更加可靠 | 任务要求、使用条件，以及实际得到的支持 |
| 保持与迁移 | 间隔之后仍能使用重要内容；面对变化后的问题能够识别关系并调整做法 | 时间间隔、任务变化的程度，以及目标是否要求长期保持 |
| 继续学习 | 能够发现自己的缺口，选择资源，利用反馈并推进陌生问题 | 已有基础、资源条件，以及学习者实际承担的判断 |
| 时间与负担 | 用在目标相关内容上的时间更充分；重复介绍背景、维护记录和无效往返的负担减少 | 能力进展、可用时间和任务期限，兼顾短期推进与长期需要 |
| 学习体验与决定权 | 学习者理解教学安排的用途，能够调整方向和投入，并愿意继续参与 | 学习者的明确反馈、当时处境及后续参与情况 |
| 连续性与可核对性 | 新对话能够承接原有目标和进度；学习者能够理解判断的依据，修订不准确或过时的信息 | 记忆是否完整表达观察条件、判断范围与个人约定 |
| 可调整性与可迁移性 | 修改个人约定后辅导能够相应调整；更换模型、客户端或组件后记忆仍可使用 | 各组成部分遵守的约定，以及实际接续中的表现 |

这些方面之间可能存在取舍。例如，完整示范能够帮助学习者尽快理解任务，独立尝试能够暴露执行中的困难；两者需要的时间和提供的学习机会不同。模型依据目标与当前状态提出安排，学习者决定其愿意承担的投入。试用中的判断同时保留结果和条件，以便解释一种安排为何有价值、何时需要调整。

## 设计哲学

### 模型依据目标与情境作出教学判断

Cairn 面向能够理解材料、使用工具并进行复杂推理的模型设计。指引提供清楚的目标、共同概念、相关信息和教学依据，模型据此选择切入点、任务、讲解、反馈与支持。这样分配责任，是为了让教学能够响应具体内容和学习者当时的状态。

模型的自主选择需要可解释的依据：当前希望推进什么能力，对学习者已有表现如何理解，这项活动能提供什么学习机会，以及何种回应会促使安排改变。学习目标、活动与表现证据之间的对应关系，为这些判断提供共同参照（Biggs, 1996）。

学习者决定方向和投入，模型协助其形成和调整目标，并在约定范围内选择具体做法。改变学习者的分工、投入或进度的安排，由模型说明差别后交由学习者决定；对话中的教学做法可以依据回应及时调整。这种自主性以学习者的约定和可核对的表现为基础，其效果通过实际使用检验。

### 以有条件的教学知识支持选择

教学原则说明学习发生的条件和需要权衡的关系。学习方法进一步保存可复用的做法，说明它想解决什么问题、适用于什么条件、可以取得什么反馈，以及在何种表现下需要调整。具体做法可以成为方法的一部分，模型依据当前情境选用和组合。

可复用性来自对条件的说明。同一种做法可以适合某种知识缺口，对另一种缺口帮助有限；同一个学习者也会随内容和能力变化而需要不同支持。系统将这些差异作为方法的组成部分，保留模型判断适用性的空间。

共同学习框架以目标、状态、任务、活动与支持、证据描述学习。讲解、阅读、实现、调试和梳理是能够组合的活动；材料的形式用于选择合适的接触和反馈方式。学习方法按其解决的问题与适用条件组织，由共同概念描述其与目标和证据的关系。

设计文档分别说明文献支持的结论、由其形成的设计推论，以及使用中得到的观察。参考文献为教学判断提供依据；Cairn 采用这些依据的方式及其实际效果，由设计说明和试用结果共同评价。

### 个人约定与可修订的认识分别保留

目标、背景、偏好和辅导约定属于学习者的个人信息，保存在其记忆中。通用的教学原则和具备适用条件的方法由插件提供。学习者调整个人安排时可以直接修改相应设定，插件升级也应保留这些个人内容。

学习者对安排的偏好，与某种做法在特定情境下取得的效果，具有不同含义。前者表达学习者希望如何学习，后者是依据表现形成的判断。模型按学习者的约定开展辅导，并把观察到的效果作为可讨论、可修订的信息。有关设定、观察与判断的详细关系见[共同学习模型](learning-model.md)和[记忆](memory.md)。

这种区分使个人定制与经验积累能够同时成立。一次顺利的活动可以留下观察，长期约定由学习者决定；已有约定也可以在需要变化时重新讨论。

### 确定性的工作由系统承担

时间记录与计算、链接解析、索引生成、同步、版本校验和写入规则等确定性工作，由服务端或插件完成。模型主要承担内容理解、教学选择、表现解释和记忆内容的组织。将两类责任分开，可以减少重复计算和机械操作对教学过程的占用。

引入机制时，优先采用能够由系统可靠完成的方式，并明确模型需要提供什么内容。系统的工作时机依据能够可靠取得的事件设计；长期对话中的学习记录与状态更新依托实际学习进展和自然停顿，保持对话续接时的连续性。具体责任由[服务端](../components/server.md)说明。

### 组成部分通过稳定约定衔接

指引、记忆服务与记忆分别承担教学说明、确定性服务和个人信息保存，通过工具接口、记忆格式与内容效力的约定衔接。每个部分明确自己提供的信息和能力，使其他部分可以据此工作。

教学模型和方法能够在共同概念下持续修订；记忆服务能够改进读取、写入和同步；学习者能够更新个人约定。新增能力按其职责归入相应组件或扩展模块，并说明对既有约定的影响。接口或格式发生变化时，按照对应的版本与兼容安排处理。整体关系见[文档总览](../README.md)。

### 记忆能够由学习者阅读和核对

记忆采用纯文本，学习者可以直接阅读和编辑。掌握状态等判断说明其依据、观察时间和适用条件，学习记录保留可追溯的过程，git 保存修改历史。学习者能够据此理解模型为何形成某项认识，并在发现误记、遗漏或判断范围不合适时提出修订。

可核对性服务于判断的改进。后续模型需要能够分辨已经观察到的表现、学习者的自述、已有推断及尚未确认的部分，而服务端负责保存、关联和返回这些信息。核对的对象包括内容含义和判断范围，具体内容组织见[记忆](memory.md)。

### 依据实际使用演进

基础版优先保证加载记忆、开展辅导和更新记忆这条基本过程。机制在两种情况下进入基础版：它是完成基本过程所必需的，或实际使用已经呈现了需要由它解决的问题。其他构想保留问题描述和重新考虑的条件，纳入[议题与决策](../decisions.md)。

使用中的问题按性质处理：个人需要通过设定调整；可以复用的教学认识整理为有适用条件的方法；模型反复出现的行为问题通过指引修订；确定性工作和组件能力的问题进入相应的系统设计。每项修改说明预期改善的结果，也关注新增的维护成本和学习负担。

试用提供调整方向的依据。观察既包含讲解、反馈和任务安排的情况，也包含学习者是否获得有价值的能力变化、是否能够持续参与，以及记忆是否减轻了接续学习的负担。历史设计资料保留为参考，在对应问题出现时重新评估其适用性。

## 产品范围与当前边界

### 核心范围与采用方式

| 范围 | 采用方式 | 取舍依据 |
|---|---|---|
| 学习过程 | 以共同学习模型指导选择，活动和支持依据目标、状态与反馈调整 | 保持目标与判断依据的连续性，同时适应不同任务和学习者 |
| 进度与目标完成 | 学习者决定推进、调整和结束，模型提供已有依据、未确认部分及取舍建议 | 目标与投入由学习者拥有，掌握判断为决定提供信息 |
| 学科内容 | 以学习材料和模型能够使用的知识支持辅导，个人记忆保存与该学习者有关的信息 | 将核心维护投入用于理解学习者与保持连续性；学科材料及作品保留其各自用途 |
| 掌握表示 | 用文字描述表现、条件、依据与判断范围 | 使不同对话能够理解判断的实际含义，并由学习者核对 |
| 保持与复习 | 服务端提供时间信息，模型结合目标重要性和当前学习选择回顾或检验 | 把长期保持与正在进行的学习联系起来，并保留学习者对投入的决定权 |
| 记录与核对 | 以文本、链接和修改历史支持人的核对，服务端保证约定的读写行为 | 将内容判断交给学习者与模型，将确定性维护交给系统 |
| 教学知识 | 保存原则、适用条件和可选做法，以实际回应调整采用方式 | 使方法能够复用，也使其适用范围可以修订 |

### 基础版的范围

基础版处于设计阶段，现行实现为 v1。本文描述基础版的目标与取舍，现行代码的行为仍由根目录 [DESIGN.md](../../DESIGN.md) 和 [server/SPEC.md](../../server/SPEC.md)说明。各设计文档与实现的状态由[文档总览](../README.md)和[议题与决策](../decisions.md)关联。

- **个人使用。** 一个数据仓库对应一位学习者，支持本地安装和服务器部署。其他学习者可以各自安装并维护自己的数据仓库；账号体系与托管服务属于后续产品范围。
- **学习活动。** 共同学习框架覆盖材料阅读、讲解、练习、实现、调试和梳理等活动。示例主要面向计算机科学与 AI 基础设施方向；领域方法的积累按实际需要推进，模型可以依据共同框架处理尚无专门方法的活动。
- **记忆维护。** 基础版包含学习过程中的记录和阶段性状态更新。跨多次对话的系统性记忆整理、对话之间的变更通知，以及更细的时间信息处理，保留为扩展事项。多个对话通过重新加载记忆取得其他对话的更新。
- **笔记与作品。** 梳理可以作为学习活动，成稿由学习者保存和使用。按模板生成、跨客户端保存以及笔记之间的链接由后续笔记模块处理。
- **长期回顾。** 项目结束后，相关内容可以在后续学习中再次涉及，也可以由学习者主动要求回顾。主动提醒与项目结束后的持续安排属于后续扩展。
- **效果观察。** 基础版利用学习表现、记忆和学习者反馈判断辅导的价值。独立的教学效果评估模块保留为扩展事项。
- **客户端能力。** 技能与 MCP 构成共同的接入基础，命令、钩子和子代理等增强能力依赖客户端支持。指引和学习方法以中文撰写，客户端支持情况见[插件](../components/plugin.md)。
