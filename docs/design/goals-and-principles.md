# 目标、边界与设计哲学

本文说明 Cairn 基础版要达到的目标、不包含的内容，以及设计中出现取舍时依据的立场。它是设计层的第一份文档，辅导和记忆两部分的设计分别见[辅导](tutoring.md)和[记忆](memory.md)。各部分的确认状态见[议题与决策](../decisions.md)。

## 三个层次

系统的目标、设计哲学和模型的教学原则回答不同的问题，面向的对象和写入的位置也不同。

| 层次 | 回答的问题 | 面向的对象 | 所在的位置 |
|---|---|---|---|
| 目标 | 系统要达到什么结果，以什么标准判断是否达到 | 使用者、贡献者 | 本文 |
| 设计哲学 | 设计中出现取舍时依据什么立场 | 设计者、贡献者 | 本文 |
| 教学原则 | 模型在辅导时遵循什么 | 模型 | 指引正文；设计依据见[辅导](tutoring.md) |

三个层次之间的关系是：目标限定系统的范围；设计哲学决定为实现目标而作出的各项设计选择，其中包括指引的写法；教学原则是指引的内容，由学习理论推出，写法受设计哲学约束。总体结构、记忆格式、工具和插件实现是这三个层次的具体化，不构成另一个原则层次。

区分层次有两方面的作用。第一，各层次的陈述写入不同的位置：设计哲学不写入指引，因为模型在辅导时不需要了解设计立场；教学原则不列为设计原则，因为它是指引的内容，而不是设计取舍的依据。第二，各层次的修改依据不同：目标随使用者的需要调整，设计哲学随设计经验调整，教学原则随学习理论和使用中的观察调整。

## 目标

Cairn 是面向个人的 AI 辅助学习系统，以客户端插件的形式提供。系统的目标有三项。

**学习记忆的统一与可迁移。** 与学习相关的记忆（学习者的情况、目标和约定，学习进度，掌握状态，学习特征，学习记录）集中保存在学习者自己的数据仓库中，采用纯文本格式，不依赖特定的客户端或模型。更换客户端或模型后，学习可以从原有状态继续。

**基于充分了解的个性化辅导。** 模型在开始辅导时获得学习者的设定和当前的学习状态，并据此教学。辅导以长期掌握为衡量标准：学习者在脱离辅助的条件下能够解释和应用所学内容，并在此基础上继续学习。

**随使用演进。** 学习者可以通过设定定义自己的目标、偏好和对辅导方式的约定；模型在辅导中识别并记录对该学习者有效的方式，并可以建议把其中稳定的部分写入设定；系统的各组成部分可以独立升级，升级不影响已有的记忆。

判断目标是否达到的标准如下。

| 目标 | 可观察的标准 |
|---|---|
| 统一与可迁移 | 更换客户端或模型后，模型在新的对话开始时能够准确说明当前的学习进度和掌握状态，不需要学习者重新介绍。数据仓库中的任一页面可以用普通的文本编辑器阅读 |
| 个性化辅导 | 对已有充分依据的内容，模型直接在其基础上继续教学；对依据不足或间隔较长的内容，模型在教学中安排检验。学习者能够从页面中了解每项判断的依据 |
| 随使用演进 | 学习者修改一项设定后，其后的辅导按新的设定进行，不需要修改插件。插件升级后，原有的记忆无需手工调整即可继续使用 |

## 边界

边界分为两类。第一类是有意不采用的常见做法，属于设计上的选择，不随版本改变。第二类是当前版本的限制，由现阶段的范围决定，会在后续版本中逐步解除。

### 有意不采用的常见做法

| 常见做法 | 不采用的原因 | 本系统的做法 |
|---|---|---|
| 固定的教学流程和掌握门槛：按预设步骤推进，达到阈值后进入下一单元 | 预设的流程和阈值难以适应不同的学习者、内容和学习类型；旗舰模型依据目标和学习状态作出的判断更贴合具体情境 | 指引陈述目标和教学原则；学习方法作为参考提供，可以由学习者的设定调整 |
| 维护学科知识库：知识图谱、题库、针对教材的检索增强 | 学科知识已包含在模型和学习材料中，另行维护的成本高且容易过时；系统特有的价值在于对学习者的了解 | 记忆只保存与学习者有关的信息；学习材料原样提供给模型阅读 |
| 以数值表示掌握程度：百分比、等级分 | 数值没有可核对的含义，容易被当作精确结论使用，不同模型给出的数值也不可比 | 以文字陈述判断，并说明依据、观察时间和确信程度 |
| 由系统强制执行复习计划：按固定算法排期并要求完成 | 固定排期与当前的学习内容脱节，并使检验与学习活动分离 | 服务端提供各项内容距上次涉及的时间，由模型在教学中择机引入检验 |
| 机器可审计的证据链：为每项判断建立结构化证据，由服务端校验 | 维护成本高，约束集中于记录而不是教学 | 人可核对：纯文本，判断附依据和时间，学习记录只追加，git 保留修改历史 |

### 当前版本的限制

- 一个数据仓库对应一位学习者。多人使用通过各自安装插件、各自建立数据仓库实现；账号体系和托管服务不在当前范围内。
- 学习方法按讲解型和实践型两种学习类型编写，示例面向计算机科学与 AI 基础设施方向。论文阅读等其他学习活动的学习方法有待调研，在此之前由模型依据教学原则安排。
- 不包含笔记生成、记忆整理和教学效果评估等扩展模块。
- 学习项目结束后，其中没有被之后的学习再次涉及的内容，系统不会主动安排检验；学习者可以随时要求回顾。
- 多个对话同时进行时，写入不会相互覆盖，但一个对话不会得知其他对话所作的更新，直到它重新加载记忆（见[记忆](memory.md)中“对话”一节）。
- 指引和学习方法以中文撰写。
- 依赖客户端对技能和 MCP 的支持；命令、钩子和子代理等增强功能只在部分客户端生效（见[插件](../components/plugin.md)）。

## 设计哲学

设计哲学是设计中出现取舍时所依据的立场，共七条。每一条先陈述立场，再说明理由和它在设计中的具体含义。

**1. 模型为主、目标导向。** 系统面向旗舰模型设计。指引陈述目标、原理和模型可以使用的信息，具体做法由模型判断；不规定教学流程，不针对特定情形预设处理方式。否定性的规定只在两种情况下写入：一是实际使用中反复出现的不当做法，二是由当前系统的限制所决定的不可行做法。理由是模型的能力持续提高，固定流程和细则带来的收益随之下降，并且会妨碍模型依据具体情境作出判断。

**2. 有理论依据。** 教学原则由学习科学中证据较为充分的结论推出，每一条说明它所依据的学习条件，使模型能够在原则未覆盖的情形下自行推理。系统机制在引入时须说明所解决的问题及其依据；不能说明的机制不引入。

**3. 可定义的内容归入记忆。** 凡是由学习者定义、因学习者而异的内容，包括目标、背景、偏好和对辅导方式的约定，均作为学习者设定保存在记忆中，不写入插件。插件只包含对所有学习者适用的内容，包括教学原则和学习方法；学习者的设定优先于插件中的做法。这样，学习者调整系统的行为时不需要修改插件，插件升级也不会覆盖学习者的设定。

**4. 确定性的工作由系统承担。** 能够由服务端或插件确定完成的事项，包括时间的记录与计算、链接解析、索引生成、同步、版本校验和写入规则的保证，不交给模型处理。引入一项机制时，优先选择不需要模型额外配合的实现方式。理由是模型的注意力应当用于教学判断；需要模型逐步配合的机制会增加指引的长度，并且在长对话中执行不稳定。同样的道理，系统不依赖无法可靠得知的事件：对话何时结束无法由服务端或模型确定，因此任何步骤都不以对话结束为前提。

**5. 组成部分解耦，可扩展、可替换。** 指引、记忆服务和记忆三个部分通过记忆格式和工具接口相互约定，各自可以独立修改和替换。不同学习类型的学习方法相互独立。新增的功能以扩展模块的形式加入，不修改基础部分。记忆格式是各部分之间最稳定的约定，它的变更需要版本号和迁移说明。

**6. 人可核对。** 记忆以纯文本保存，学习者可以直接阅读和编辑。每项判断附有依据和观察时间，学习记录只追加，git 保留全部修改历史。学习者据此可以核对任何一项判断的来源。系统不要求服务端对判断的正确性作形式化校验。

**7. 依据实际使用演进。** 基础版只包含进行学习并在历次对话之间保持学习状态所必需的部分。一项机制只在两种情况下加入：缺少它时基础流程（加载记忆、辅导、更新记忆）无法完成，或者实际使用中已经出现它要解决的问题。其余的想法登记为暂缓事项，并写明重新考虑的条件（见[议题与决策](../decisions.md)）。2026 年 10 月的重构讨论记录作为设计储备保留，在对应的问题出现时取用。

|---|---|
| 1、2 | 指引的写法和教学原则的依据，见[辅导](tutoring.md) |
| 3 | 学习者设定的效力，以及学习方法与设定的分工，见[记忆](memory.md)和[辅导](tutoring.md) |
| 4 | 工具的职责和服务端保证的规则，见[服务端](../components/server.md) |
| 5 | 三个组成部分之间的约定，见[文档总览](../README.md)；插件的结构和版本安排，见[插件](../components/plugin.md) |
| 6 | 记忆的格式，见[记忆](memory.md)和[数据仓库](../components/data-repo.md) |
| 7 | 基础版的范围和暂缓的事项，见[议题与决策](../decisions.md) |
