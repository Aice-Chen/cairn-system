# 记忆：价值边界、语义与更新

本文说明 Cairn 长期记忆的设计：各组成部分分别承担什么独特价值、如何避免内容同质化与重复双写、四种内容语义与两级行动效力、读写与淘汰重选规则、双链与页面更新时间信息，以及跨对话的更新与延续机制。文件目录与具体语法见[数据仓库](../components/data-repo.md)，读写工具与服务端规则见[服务端](../components/server.md)。

## 记忆的范围与组成部分的价值边界

记忆是系统保存的、与这位学习者个人有关的信息，以纯文本保存在学习者私有的 git 数据仓库中。学习材料（`sources/`）、通用学科知识以及学习者产出的代码或笔记作品均不属于记忆。

为避免“记录与掌握状态重复抄写”以及“学习特征与具体知识点混淆”，记忆的五个子部分按**回答的问题、组织维度与生命周期**切分职责：

| 组成部分 | 回答的核心问题 | 组织单位与生命周期 | 独特价值（为何不可互相替代） |
|---|---|---|---|
| **学习者设定**（`settings/`） | 学习者有什么背景，希望达成什么目标，约定了怎样的协作方式？ | 通用一页 + 每个项目一页；仅经学习者确认后更新 | 保存学习者的背景自述，以及当前有效的个人目标、使用条件与持续协作约定，提供跨对话一致的起点与权限前提 |
| **学习记录**（`records/`） | 过去的学习过程中具体发生了什么？ | 按日期归档的事件流，只追加不修改 | 保存压缩前的过程细节：单次尝试、卡点转折、获得的具体支持、决定变更经过。状态页随时间会被重写和裁剪，只有记录能用于事后核对依据或回溯演变轨迹 |
| **掌握状态**（`state/mastery/`） | 在某项领域概念、机制或能力上，目前处于什么水平？ | 按**可复用的概念、机制或能力**建页；随新证据合成并覆盖旧结论 | 跨项目复用的当前能力认识。新对话无需重读历史流水账即可获知最新能力边界；多次观察后只保留合成后的当前判断与关键依据日期和条件，不堆砌历次过程 |
| **学习特征**（`state/traits/`） | 面对新内容时，这位学习者怎么切入更有效、常在哪里出现偏差？ | 按**跨内容可迁移的认知与协作模式**建页；随新表现修订 | 与具体学科内容解耦。`mastery/` 关心“是否掌握注意力机制”，`traits/` 关心“接触复杂机制时先追踪单条实例链路是否比先看静态分层图更易建立理解”。它为新项目提供初始辅导假设 |
| **学习进度**（`state/progress/`） | 当前项目工作推进到了什么状态、学习者确定下一步做什么？ | 每个学习项目一页；随阶段推进覆盖更新 | 承接单个项目的连续工作：进展概况、当前工作状态（停留位置、已发生的尝试结果、有依据的当前分析认识、正在开展的步骤）、学习者要求保留的备忘及已确定的下一步安排 |

当某个概念仅发生过第一次交互时，`records/` 中的单次事件与 `mastery/` 中的初始判断在信息上自然相近；随着后续交互增多，两者迅速分化：`records/` 继续按时间留存每次具体事件，而 `mastery/` 用最新证据合并、修正并覆盖已被超越的旧快照，保持页面简明。

## 内容的语义与行动效力

### 四种内容语义

记忆中的文字按实际含义与来源分为四种，其解释方式不因所在目录而混淆：

| 语义 | 含义 | 示例 | 在辅导中的效力与用法 |
|---|---|---|---|
| **决定与约定** | 学习者作出的选择：目标、使用条件、投入上限、协作规则、选定的下一步 | “本项目核心模块先由我自己写，卡住时只提示方向” | 在适用范围、期限与成立条件内约束教学安排 |
| **自述** | 学习者对自身经历、已有基础、把握度或感受的陈述 | “以前写过 Go 并发，但没接触过 GPU 编程” | 了解起点的个人背景信号；随实际表现补充核实，不作为行动指令 |
| **观察** | 具体条件下实际发生的尝试、回应、错误、修正与事件 | “2026-11-14 在提示检查最后两维形状后，自行修正了掩码广播错误” | 形成判断的事实依据；保留当时的支持条件与信息来源（直接观察或事后自述） |
| **推断** | 模型基于有限观察归纳出的当前认识：能力边界、问题原因分析、特征假设 | “能无提示说明缩放因子原理；实现多维广播时仍需形状检查提示” | 当前工作认识；写明依据范围或暂定性质，随新证据出现随时修订 |

### 两级行动效力与接续设计取舍

记忆内容对后续行动的效力分为两级：
- **约束后续安排的只有学习者的执行决定**：即学习者在有效范围与期限内明确采用的目标、协作约定和下一步安排。跨项目约定保存在通用设定，单项目约定保存在项目设定；带期限的安排（如“考前一周采用闭卷推导”）到期自然结束；一次性接续决定（如“下次先练一下张量变形”）执行完毕后转为历史进度，不再持续约束后续对话。
- **其余内容均只供接续参考**：包括学习者的背景自述、模型对能力与特征的推断、当前工作中的分析判断、上一轮正在开展的局部步骤，以及学习者要求保留的备选备忘。后续对话结合当时的即时请求与目标决定是否沿用。

这里需要明确两项设计边界：

1. **区分“决定保存信息”与“决定执行行动”**：写入者不等于决定者，且学习者要求保存某项信息不等于决定执行其中的行动。例如学习者表示“先把这两种实现方案记下来，我之后再选”，体现了学习者要求在项目进度中保存备选方案的决定，但两种方案本身仍属于尚未选定的备忘，后续对话不将其视为已敲定的执行指令。
2. **保留当前分析状态，同时取消预设待办栏目**：复杂阅读、推导或实验分析跨越多次对话时，如果进度页只记录章节物理位置而排除“已验证排除了哪些方向、当前依据现象形成了什么初步原因推断、上一轮正在按什么步骤对比”，后续模型就必须反复检索和重读历史记录才能恢复工作脉络，接续成本随对话次数增加而上升。反之，如果设置固定的“未决问题 / 候选建议”栏目，模型在总结时又容易把证据未覆盖的空白或单方面构想填成待办清单，诱导后续模型机械顺延。因此，Cairn 的取舍是：**允许保存有依据、对恢复工作脉络有价值的当前分析认识与进行中的步骤（写明来源与暂定性质），同时取消“未决问题、待考察事项、候选建议”等固定待办槽位。**

## 写入、归属、淘汰重选与读取规则

模型在写入学习记录、更新状态页面、编写 `summary` 摘要及读取记忆时，统一遵循以下五条规则：

**1. 保持来源、范围和效力。**  
推断经过概括或转述仍是推断，带有支持条件的表现压缩进 200 字 `summary` 时仍须保留关键条件（如“在形状提示下完成”不能压缩成“已能独立实现”）。多次引用同一历史观察时，其证据强度仍只对应那一次观察。

**2. 严格区分学习者产出与模型顺势补全（如实归属）。**  
辅导交流中，当学习者给出模糊、跳跃或仅对了一半的回答，而模型顺着话头替其补全了关键推理链条时，记录与掌握状态只把**学习者自己明确说出或独立完成的部分**计入其能力表现；模型补全的逻辑环节如实记作本次的“支持条件”，防止代为补全的内容混淆长期能力判断。

**3. 陈述已有事实与当前认识，不将空白或构想写成待办条目。**  
模型在做阶段总结时，容易受日常交接文档习惯影响，将证据未覆盖的情境、未验证的猜想或单方面的下一步构想写成“尚待观察、待后续检验、待查问题、建议下次练习”等条目。写入时应以陈述句如实表达已发生的事件、已有依据支持的认识（含对应明确目标的已观察差距、注明暂定性质的当前问题分析）以及学习者本人的决定或备忘要求；未覆盖的情境留白，下一步做什么留给后续对话结合当时的请求当场判断。各目录具体容纳的内容范围见[`references/memory-format.md`](../../skills/cairn/references/memory-format.md)。

**4. 更新状态与摘要时主动淘汰重选。**  
阶段性更新不是只往状态页末尾追加新段落。每次修订 `state/` 页面及其 `summary` 时，模型结合当前仍有持续用途的信息重新整合：已被新表现超越的早期局部卡点予以覆盖或浓缩为背景，已解决的临时问题和已完成的单次安排从当前进度中移除，使状态页始终反映精炼的当前认识。

**5. 详略与后续理解及决策价值相称。**  
简单进展或常规观察一行即可；只有涉及持续约定、反复出现的障碍、关键能力边界或复杂任务的接续状态时，才展开必要的任务与条件细节。

以上规则共同对应一项检验标准：**脱离本次对话后，后续读者能否仅凭页面文字准确还原它当时指什么、依赖什么依据与条件，并判断它在新的目标与请求下是否适用。**

## 三类记忆的组织细节

### 学习者设定（`settings/`）

设定保存学习者本人的背景自述，以及明确采用的目标、使用条件与持续协作约定，按作用范围分为两级：
- **通用设定**（`settings/general.md`）：个人背景自述、长期方向与跨项目通用的辅导约定，每次 `start_session` 加载全文。
- **项目设定**（`settings/projects/<项目>.md`，可选）：特定学习项目的目标、使用条件、时间约束与专门约定，指定该项目时加载全文，其余项目仅返回名称与摘要。

更细的情境或时间条件直接用自然语言写在具体约定条目内，不再拆分更多目录层级。范围更具体的约定优先于宽泛约定；个人设定优先于插件指引的默认做法。设定的新建与修改必须经学习者明确表态或确认，由专用工具 `update_settings` 写入并记录确认说明。背景自述作为了解起点的参考，后续实际表现与自述不同时在状态页如实记录观察结果，自述本身是否修改由学习者决定。

### 学习状态（`state/`）

- **学习进度**（`state/progress/<项目>.md`）：记录项目材料路径、进展概况、当前工作状态（停留位置、已发生的尝试结果、有依据且标明暂定性质的当前分析认识、正在开展的步骤）、学习者要求保留的备忘，以及学习者已确定的下一步安排。当新对话中学习者提出新的具体请求时，以当前请求为准；当学习者要求“接着上次继续”时，结合已定安排与当前工作状态接续。
- **掌握状态**（`state/mastery/`）：页面优先按**可复用的概念、机制或能力**命名（如 `缩放点积注意力`、`内存合并访问`），避免按一次性任务命名（如“作业一第二题”），以便跨项目共享和关联。一个页面可包含围绕同一主题的多项判断（如原理理解与编码实现），每项写明当前能力边界、核心依据（表现发生日期、任务、支持条件、信息来源）及影响选择时的确信度说明。
- **学习特征**（`state/traits/`）：记录带观察范围、随新表现修订的跨内容辅导假设，主要包括三类信息：（1）有效的认知切入与表征方式（如面对复杂机制先追踪单条实例优于先看分层抽象）；（2）跨领域的典型执行习惯或盲区（如动手实现前易忽略形状或边界不变量）；（3）自我评估倾向（如听懂原理后易高估独立实现速度）。每条特征注明已观察到的项目/任务范围（出现过反例时如实注明例外），保持精炼（常规维持在一两页规模以便 `start_session` 直接返回全文）。

### 学习记录（`records/`）

学习记录保存在 `records/YYYY-MM-DD.md` 中，按日期每天一个文件，每条记录由服务端写入时间、所属项目和可选的对话标记。按日期而非按对话分文件的原因有三点：一是每条记录都具备确定时间，而对话标记在部分客户端可能缺失或中途更替，记录落盘位置不应依赖可能缺失的标记；二是单次对话可能跨越数周，按日期切分边界稳定；三是回查历史依据时主要按日期定位。

发现既有记录与事实不符时，通过 `add_record_entry` 追加一条更正说明（注明所更正条目的日期与时间），并据此修订相应的学习状态页面，不删改历史记录原文。

## 页面、链接、索引与时间信息

**页面与粒度**：每个 `.md` 文件是一个页面，frontmatter 中包含必填的单行 `summary`（不超过 200 字符）。页面粒度由模型按三条实用标准把握：能用清晰的概念或主题名指称、能独立更新、能用一两句话概括；随内容演进可通过 `move_page` 重命名或通过 `remove_page` 合并拆分。

**双链 `[[页面名]]` 的定位**：双链只承担**语义关联与阅读导航**两项职责，不参与时间统计：
1. 供服务端在 `start_session` 时从当前项目进度页提取直接关联的掌握状态页摘要，以及供 `get_related_pages` 查找上下游关联页面；
2. 供学习者在 Obsidian 中点击双向跳转核对。模型漏写个别双链只影响局部跳转便利性，不影响系统计时或状态准确性。

**掌握状态全量名称清单与跨项目关联**：服务端自动解析所有页面的 frontmatter 生成索引。为避免跨项目学习时产生“概念孤岛”（例如在 `vllm` 项目中看不见此前在 `cs336` 中建立的 `[[缩放点积注意力]]` 页面而重复创建同义的 `[[注意力计算]]`），`start_session` 除了返回进度概况、学习特征全文及当前直接关联掌握状态页的完整摘要外，还会返回**其余全部掌握状态页面的轻量名称清单（含最近更新日期）**。个人数年积累的主题级页面通常在数百页以内，名称清单体积较小，使模型在开场时即可看见已有的领域概念目录，按需调用 `read_pages` 查阅详情并沿用既有名称建立链接。

**基于页面内容变更历史的时间信息及其边界**：服务端不通过解析 `records/` 双链来计算页面时间，也不单独维护脱离 git 仓库的数据库，而是从每个学习状态页面的 git 提交历史（启用重命名追踪 `--follow`）中统计实际内容变更提交——包含 `write_page`、`edit_page` 提交以及学习者直接修改页面内容的提交，**仅排除 `move_page`、`remove_page` 触发的重命名与双链机械改写提交**——计算三项确定信息：
- **首次创建日期**：该页面首次建立的日期；
- **最近更新日期**：该页面最近一次发生内容变更提交的日期；
- **累计更新天数**：该页面发生过上述内容变更提交的不同日期总数。

在使用这项时间信息时，需区分**页面维护时间**与**实际学习表现时间**：单页可能包含多项能力判断，局部文字精简、人工补充修改或更新其中一项也会刷新整个文件的最近更新日期。因此，服务端返回的页面时间信息仅作为识别“哪些页面较久未发生内容更新”的粗筛索引；判断某项具体能力距离上次实际练习或检验过了多久，以页面正文中记录的表现发生日期为准。

## 记录时机、阶段性更新与跨对话延续

系统不记录对话的开始与结束，任何流程都不依赖无法可靠捕获的“会话关闭”事件。

**按观察闭环与阶段节点写入及其取舍**：  
在日常多轮讲解与探讨过程中，模型不需要每两三轮调用写入工具，以免在思路尚未充分展开时过早给表现定性，同时也减少网页端远程 MCP 可能出现的写操作确认打断。写入按两类时机进行：
- **学习者的明确决定或目标变更**：一旦确认，当场调用记录或设定工具落盘；
- **学习表现与状态修订**：待一个局部观察闭环完整（如一次问题分析、尝试与修正走完）或进入自然阶段停顿（主题切换、阶段小结、学习者准备离开）时，调用 `add_record_entry` 记录本段有价值的事件，并同步调用 `write_page` / `edit_page` 更新涉及的进度、掌握状态和学习特征页面。

这项安排的代价是：若对话在局部观察闭环完成前意外中断且后续不再继续，中断前这几轮尚未写入工具的交流细节不会进入记录。系统接受这一局部损耗，以换取日常教学互动的连贯性。在支持插件钩子（Hooks）的本地客户端中，可利用上下文压缩前或停止事件提醒模型补齐尚未落盘的阶段记录，作为可选增强。

**同步提交与异步远端推送**：  
服务端串行执行写入并立即完成本地 git 提交后即返回工具结果；若配置了远端仓库，后台异步执行拉取合并与 `git push`（推送异常或远端冲突在下一次工具返回中告知）。这一机制对远程 HTTP 服务端和本地 stdio 服务端同样适用，避免了每次写入的网络等待。

**状态写入后的新增记录提示**：  
服务端通过对比 `records/` 条目的写入时间与 `state/` 目录最近一次由 `write_page` 或 `edit_page` 产生的状态写入提交时间，在 `start_session` 中列出晚于该基准时间的新增记录（页面重命名、双链改写或学习者在本地直接编辑页面不会推进该比较基准，避免掩盖尚未整理进状态的记录）。这为“上次对话写了记录但尚未执行状态页更新即关闭”的常见情形提供了恢复线索；但若一次对话先后写入多条记录、仅将其中一部分整理进状态页便中断，单纯的时间比较不会单独标出剩余记录，此时由模型结合 `start_session` 默认返回的最近日期记录自行参考。

**并发写入与学习者直接编辑**：  
服务端无会话级内存状态。多窗口并发写入时，`records/` 只追加，`state/` 通过读取时返回的版本标识（`base_version`）做乐观并发校验，`settings/` 须附确认说明。学习者在本地直接用编辑器或 Obsidian 修改页面后，服务端在下次 `start_session` 中列出最近被人工直接修改过的页面；模型按修改内容的语义（修改设定视为新决定，补充经历视为自述，修正判断结合依据核对）处理。
