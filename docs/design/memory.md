# 记忆：语义、组织与更新

本文说明 Cairn 的记忆：保存什么，各项内容的性质和效力，怎样组织，怎样写入、概括和读取，以及怎样更新。共同的概念见[共同学习模型](learning-model.md)；目录和文件格式见[数据仓库](../components/data-repo.md)；读写记忆的工具见[服务端](../components/server.md)。各项内容的确认状态见[议题与决策](../decisions.md)。

## 记忆保存什么

记忆是系统保存的、与学习者有关的信息，用于理解学习者、延续学习和调整辅导。它归学习者所有，以纯文本保存在学习者的数据仓库中，学习者可以直接阅读和编辑。

以下内容不属于记忆：
- **学习材料。** 材料与记忆存放在同一个数据目录下，由记忆服务提供读取。
- **学科知识。** 记忆只保存与学习者有关的信息。
- **学习者的作品。** 作品由学习者保存和使用；学习者在完成作品时的表现，记入学习记录和学习状态。

## 内容的语义

记忆中的内容按含义分为四种，使用方式各不相同。

| 语义 | 含义 | 例子 | 在辅导中的使用 |
|---|---|---|---|
| 决定与约定 | 学习者作出的选择：目标、使用条件、投入、对辅导方式的约定、选定的安排 | “这个项目的推导题先让我独立尝试” | 约束教学安排，只能由学习者改变 |
| 自述 | 学习者对自己的经历、基础和感受的陈述 | “我学过线性代数，不熟练” | 了解学习者的起点；由之后的表现补充或修正，不作为指令 |
| 观察 | 学习者在具体条件下的表现及其结果，以及学习中发生的事件 | “在一次维度提示后，自行修正了掩码的广播错误” | 判断的依据；保留发生的条件和信息来源 |
| 推断 | 模型依据有限的表现作出的判断：能力、困难、教学方式的效果 | “能解释缩放因子的作用；实现中的维度错误需要提示才能发现” | 当前最好的认识；写明依据和范围，出现新的依据时修订 |

此前的规定是“设定整体是指令、记录整体是事实、状态整体是推断”，即以存放的位置决定效力。但设定中也有自述，记录中也会出现推断；按语义区分，效力才与内容的实际含义一致。这一划分取代了此前的规定。

## 行动效力

**行动的约束只来自学习者的决定。** 其余内容，包括模型提出或采用的安排、推断和学习者的自述，都是供之后的辅导参考的信息。

这样划分有两点理由。

**第一，写下内容的一方，与作出决定的一方，是两回事。** 模型可以记下学习者的决定，这些决定因此约束之后的辅导。模型自己作出的安排，即使已经开始执行，之后的模型也可以依据当前的目标继续或调整，因为它与当初作出安排的模型拥有同样的授权。

**第二，“已经采用、正在进行”是进度页中记录的状态，不需要单独的效力类别。** 如果把它当作约束，过时的安排会在之后的对话中继续支配学习。

学习者的决定怎样成立：学习者在对话中明确作出，或者对模型的建议明确同意。学习材料和任务中的要求，不会因为学习者选择了这项任务而自动成立；它们由模型说明，由学习者决定是否采用（见[辅导](tutoring.md)中的“学习材料与任务要求”）。

## 组织与默认的语义

记忆分为三部分，每部分有默认的语义；偏离默认时，在正文中标明。

| 部分 | 默认的语义 | 其中可能出现的其他内容 |
|---|---|---|
| 学习者设定 | 学习者的决定与约定 | 学习者的自述（背景、已有基础），作为背景理解 |
| 学习状态 | 推断，以及进度的事实 | 学习者决定的接续安排，标明是学习者的决定；模型的建议，标明是建议 |
| 学习记录 | 观察 | 学习者当时作出的决定和提出的要求，作为事件记录；涉及推断时标明 |

各类内容当前有效的版本保存在固定的位置。

| 内容 | 当前版本的位置 | 历史的位置 |
|---|---|---|
| 持续适用的目标与约定 | 相应范围的设定：通用设定或项目设定 | 决定作出和改变的经过记入学习记录 |
| 项目的进展与接续安排 | 进度页 | 学习记录 |
| 对能力、困难和特征的判断 | 掌握状态和学习特征页面 | 依据在学习记录中，修改历史在 git 中 |

持续适用的约定只保存在设定中。原因是设定的写入需要学习者确认（见[服务端](../components/server.md)）；这样，约束之后辅导的内容都经过学习者的确认。

## 写入、概括和读取的规则

以下四条规则适用于模型对记忆的全部写入，包括页面的摘要。规则本身写入指引；本节说明它们的理由。

**1. 写入、概括和读取时，保持内容原有的来源、范围和效力。**
- 推断转述之后仍是推断。
- 一项建议写进摘要，仍然是建议。
- 有条件的判断在概括时保留它的条件。

摘要是读取最多的文字，索引和加载结果都会返回摘要。压缩时最容易丢掉的就是条件，这会让有限的判断看起来范围更广。

**2. 判断以依据覆盖的范围表达；与目标有关的差距写明对应的目标；不列出尚未观察的方面。** 一次观察没有覆盖的情境几乎可以无限展开，其中哪些重要，取决于读取时的目标。

假如格式要求模型在形成判断的同时列出“仍需考察”的方面，会有两个后果：
- 写入时，模型会列出与目标无关的检验项；
- 读取时，之后的模型会把这些表述当作待办执行，而检验什么，本应由行动时的模型依据当前的目标决定。

与目标有关、已经确认的差距是一项判断，写明对应的目标后保存。目标改变时，读者能够看出它是否仍然适用。

**3. 只有学习者的决定约束行动。** 见上文的“行动效力”。

**4. 记录的详略与它对之后决策的影响相称。** 简单的表现一句话即可。不确定性只在会影响理解或选择时写出，并说明它的来源。

四条规则有一个共同的检验标准：**脱离这次对话之后，读者能够准确理解一项内容当时指什么，并判断它现在是否适用。** 例如：
- “为这次考试准备，无提示的推导仍不稳定”写明了目标和条件。考试结束后，它的行动意义改变了，含义仍然清楚。
- “仍需加强推导”没有目标和条件，会在之后持续产生误导。

## 学习者设定

学习者设定保存学习者对自己的情况、目标和辅导方式所作的陈述与约定。它的作用相当于编码代理所使用的 AGENTS.md：内容由学习者决定，以自然语言书写，在开始时加载。

设定按适用范围分为两级。

| 级别 | 适用范围 | 内容 | 加载 |
|---|---|---|---|
| 通用设定 | 全部学习 | 背景、长期方向、通用的辅导约定 | 每次加载 |
| 项目设定 | 某一学习项目 | 项目目标及其使用条件、期限、专门的约定 | 当前学习项目为该项目时加载 |

通用设定是一个页面；项目设定每个项目一个页面，可选。

约定可以附带更具体的条件，例如“准备这次考试时，推导题先让我独立尝试”。条件写在约定之中，不另设级别。不一致时的优先关系：
- 范围不同的约定不一致时，以范围更具体的为准；
- 设定与指引不一致时，以设定为准。

此前的“类型设定”随学习类型的划分一同废弃。类型设定原本也是每次加载，与通用设定的加载方式相同，合并到通用设定后功能不变。

设定由学习者决定，模型可以起草和建议。出现以下情况时，模型在学习的自然停顿处建议写入设定，说明内容和适用范围，经学习者确认后写入：
- 学习者提出了今后持续适用的要求；
- 某种做法经多次观察证明对该学习者有效。

学习者也可以直接编辑设定。

设定中的自述是了解学习者的起点。之后的表现与自述不一致时，学习状态写明观察到的情况及其条件；设定中的自述保留原有的时间和含义，是否修改由学习者决定。

## 学习状态

学习状态描述学习者当前的情况，分为三种，每种在数据仓库中有单独的目录。

- **学习进度。** 每个学习项目一个进度页，记录基本信息、大纲或里程碑、当前位置、尚未解决的问题和接续安排。完成某项材料或任务是进度中的事实，其中体现的能力由掌握状态说明。接续安排中，学习者决定的与模型建议的分别标明。
- **掌握状态。** 对学习者能力的判断。每项判断写明能力的描述、依据（任务、支持条件、时间和信息来源）和确信程度；一个页面可以包含多项判断。同一项能力在不同条件下可能表现不同，判断保留这种差异。
- **学习特征。** 学习者表现出的、较为稳定或跨内容适用、可能有助于之后辅导的特征，范围不限于对教学方式的反应。特征以观察到的范围为界，例如“在本项目两次张量变形的任务中，画出各维度后自行发现了错误”；它是否适用于其他内容，需要进一步观察。

学习状态中的内容都是推断：由此前的模型依据有限的表现作出，之后的模型以学习者当前的表现验证，在出现新的依据时修订。

## 学习记录

学习记录保存学习过程中发生的事，包括：
- 学习者的尝试、回答、错误和修正；
- 学习者得到的支持；
- 学习者提出的要求和作出的决定；
- 目标和安排的变化。

每条记录写明理解它所需的条件：学习者实际完成了哪些部分，材料、提示或模型承担了哪些部分，结果如何，以及这是在当前对话中的观察，还是学习者事后的陈述。

教学方式的效果通过具体的反应记录，例如采用某个类比之后，学习者纠正了哪个错误，能否在新的问题中运用。“这种方式有效”是一项判断，写入学习特征，并写明条件。

学习记录只追加：
- 发现记录有误时，追加一条更正，说明更正的是哪一条；学习状态依据更正后的信息修订。
- 页面重命名或合并时，服务端改写记录中指向该页面的链接。这是对学习记录唯一的修改。

学习记录按日期归档，每天一个文件，条目按时间顺序排列。每条记录带有服务端写入的时间、所属的学习项目，以及可选的对话标记。

之所以按日期归档、而不按对话归档，有三点原因：
- 记录的去处由每条记录都具备的时间决定，而不取决于可能缺失或变化的对话标记；
- 对话没有时间上的边界，一次对话可能持续数周；
- 记录主要按时间读取。

需要按对话查看时，用对话标记筛选。

## 页面、链接、索引与时间信息

**页面**是记忆的存取单位，即一个 Markdown 文件，长度不限。页面带有 frontmatter，其中 `summary` 字段用一两句话概括页面当前的内容；摘要同样遵守上文的四条规则。

页面是存取的单位，不是判断的单位：一个掌握状态页面可以包含多项判断。页面的粒度由模型依据内容决定。判断粒度是否合适有三条标准：
- 可以用名称引用；
- 可以独立更新；
- 可以用一两句话概括。

粒度不合适时，通过重命名、合并和拆分调整。

**链接**写作 `[[页面名]]`，与 Obsidian 的语法一致，可以出现在任何页面和学习记录中。链接是页面之间唯一的结构化关系，不区分关系类型；关系的含义由链接所在的句子说明。

**索引**由服务端依据各页面的 frontmatter 和链接生成，包含每个页面的名称、摘要和时间信息，不需要模型维护。

**时间信息**由服务端为每个学习状态页面计算，共四项：
- 首次记录的时间；
- 最近一次被涉及的时间；
- 被涉及的天数；
- 页面最近一次更新的时间。

前三项由学习记录中指向该页面的链接得出，第四项由 git 历史得出。时间信息不写入页面，因此不需要模型维护，也不会与实际情况不一致。

时间信息用于了解证据的新旧和学习的间隔。一个页面被涉及，可能对应讲解、尝试或讨论；它对判断能力提供了什么信息，需要结合记录判断。一项内容需要单独跟踪时间时，把它拆为单独的页面。

## 更新与跨对话的延续

三种内容的更新方式不同：
- **学习记录**在出现有价值的观察时随时追加。
- **学习状态**在阶段性更新时修订：一个主题结束、学习自然停顿或学习者准备离开时，模型更新这一阶段涉及的页面。
- **学习者设定**只在学习者确认后修改。

读取和更新的范围都是有限的。模型开始辅导时，得到设定、当前项目的进度页、学习特征和相关页面的摘要；相关页面由进度页和近期学习记录中的链接确定，全文按需读取。更新只涉及有新依据的页面。因此记忆增长时，每次读取和更新的内容量不会等比例增加。

系统不记录对话的开始和结束，任何步骤都不以对话结束为前提，因为对话何时结束无法可靠地得知。由此有以下安排：
- 加载记忆是只读的操作。开始学习时加载一次；对话在间隔一段时间后继续时，重新加载。
- 接续的内容写在进度页中，随阶段性更新维护。
- 对话在阶段性更新之前中止时，已追加的学习记录仍然保留；之后的对话可以从时间信息中看出，哪些页面被记录涉及之后尚未更新。

服务端不保存与对话有关的状态。多个对话同时进行时，只存在对同一批文件的并发写入，由写入规则处理：
- 学习状态的写入须提供读取时得到的版本标识，版本不一致时不写入；
- 学习记录只追加；
- 设定的修改须经学习者确认。

一个对话在重新加载记忆或读取相应的页面之前，不会得知其他对话所作的更新。

**对话标记**是学习记录上的可选标注，表明哪些记录出自同一次对话。客户端或插件提供了对话标识时，由服务端直接使用；否则由服务端在加载记忆时发放一个短标记，由模型在之后的调用中带上。对话标记有以下性质：
- 它可以缺失；基础版中没有任何规则依据它决定行为。
- 它的含义只在一个方向上成立：标记相同的记录出自同一次对话，标记不同不能说明出自不同的对话。

记录它的理由是，一条记录出自哪次对话，只能在写入时取得，事后无法补回。标记的取得方式见[服务端](../components/server.md)。

## 学习者直接编辑

数据仓库可以作为 Obsidian 库打开，学习者可以直接阅读和修改任何页面。直接编辑带来的是新的信息，按其性质处理：
- 对设定的修改，是学习者的决定；
- 对经历和能力的补充，按自述理解；
- 对记录或判断的纠正，与相应的依据一同核对。

服务端在加载记忆时，告知最近被学习者直接修改过的页面。
