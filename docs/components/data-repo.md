# 数据仓库

本文说明个人数据仓库的目录结构、文件与格式规范、完整示例以及与系统仓库的关系。数据仓库是长期记忆的存储实现；各部分记忆的价值边界、语义与更新规则见[记忆](../design/memory.md)。

## 与系统仓库的分离

Cairn 使用两个相互独立的 git 仓库：

| 仓库 | 保存内容 | 所有者 | 可见性 |
|---|---|---|---|
| 系统仓库 | 插件配置、技能（指引与格式参考）、MCP 服务端源码、初始化模板、设计文档 | 项目维护者 | 公开，不含任何个人数据 |
| 数据仓库 | 一位学习者的设定（含工作流与输出模板）、学习状态与学习记录，以及不纳入 git 的本机目录索引 `paths.local.toml` | 学习者本人 | 私有 |

数据仓库由系统仓库中的 `templates/data/` 初始化生成。两个仓库在 git 历史上完全独立：日常升级系统仓库或插件不会改动数据仓库中的文件；仅当记忆底层格式版本升级时才通过迁移脚本处理。两个仓库根目录均配置 `.gitattributes` 将 Markdown、TOML 等文本文件统一为 `eol=lf`（Windows 脚本设为 `crlf`），保证本地 Windows 环境与远程 Linux 服务器交替读写一致。

## 目录结构

```text
<数据仓库>/
├── settings/               学习者设定
│   ├── general.md            通用设定（常驻全文），初始化时唯一创建的设定文件
│   ├── projects/             项目设定，每个学习项目一页（可选，对应项目时加载全文）
│   ├── workflows/            按需设定示例子目录：外部协作与工作流规则（仅返回路径与 summary）
│   └── templates/            按需设定示例子目录：笔记与输出格式模板（仅返回路径与 summary）
├── state/                  学习状态
│   ├── progress/             学习进度，每个学习项目一页
│   ├── mastery/              掌握状态，按可复用概念、机制或能力建页（可建子目录归类）
│   └── traits/               学习特征，带观察范围、随新表现修订的跨内容辅导假设
├── records/                学习记录，按日期归档（YYYY-MM-DD.md），只追加
├── paths.local.toml        本机外部目录索引与读写边界（.gitignore 忽略，不纳入 git）
├── paths.example.toml      不含本机路径的目录索引配置示例模板
├── .gitattributes          跨系统换行符统一约定
└── FORMAT_VERSION          记忆格式版本号（基础版为 2）
```

结构说明：
- **学习项目标识符**：代表一门课程、一本书、一个代码库或一个实践专题（对应 v1 中的“资源”），用作 `state/progress/<项目>.md`、`settings/projects/<项目>.md` 以及默认材料通道子目录的名称。
- **`settings/` 的分层与渐进组织**：保存个人背景自述、目标与教学约定，以及跨客户端复用的外部协作规则、笔记重点原则与输出模板。初始化仅创建 `settings/general.md`，不预先创建空的子目录或空模板页；`workflows/`、`templates/` 等子目录随实际复杂度经学习者确认后按需建立，`start_session` 对除 `general.md` 与当前 `projects/<项目>.md` 外的全部设定页面统一只返回路径标识与 `summary`。
- **`state/` 的子目录**：固定划分为 `progress/`、`mastery/`、`traits/` 三类。`mastery/` 内部可由模型按领域建立子目录用于归组，但页面仍以文件名在 `state/` 内全局唯一标识。
- **外部材料与作品脱离 git 仓库**：学习材料与阶段笔记成稿、工程代码等作品存放在外部目录，通过 `paths.local.toml`（或服务端环境变量 `SOURCES_DIR`）定位；若使用数据仓库下的默认回退目录 `<数据仓库>/sources/`，同样由 `.gitignore` 排除。

## 记忆格式规范

本节定义服务端强制检查的格式规则，以及由 [`references/memory-format.md`](../../skills/cairn/references/memory-format.md) 传达给模型的正文组织约定。

### 名称规则

页面名称即去掉 `.md` 后缀的标识：
- **学习项目名称与 `settings/` 子目录名称**：仅由小写 ASCII 英文字母、数字和连字符 `-` 组成（如 `cs336`、`vllm-scheduler`、`workflows`、`templates`）。
- **学习状态页面名称**：可使用中文、英文字母、数字、空格和圆括号，长度不超过 80 个字符，禁止包含文件系统与双链特殊字符：`/`、`\`、`:`、`*`、`?`、`"`、`<`、`>`、`|`、`#`、`^`、`[`、`]`。名称在整个 `state/` 目录下不区分大小写唯一。`mastery/` 页面命名优先采用**可跨项目复用的概念、机制或能力名称**（如 `缩放点积注意力`、`内存合并访问`），避免采用一次性任务标题（如“作业一第三题”）。
- **设定页面名称与标识**：按需设定页文件名推荐使用小写 ASCII 字母、数字和连字符 `-`（如 `workflows/note-guide`、`templates/paper-note`，中文用途写在 `summary` 中，便于跨系统引用），亦兼容上述合法中英文字符；路径在 `settings/` 内不区分大小写唯一。跨目录调用 `read_pages` 时写作 `settings/<相对路径>`，调用 `update_settings` 时 `page` 传相对于 `settings/` 的路径（如 `general`、`projects/cs336`、`workflows/note-guide`）。

### frontmatter

每个设定页面与状态页面顶部均包含 YAML frontmatter，服务端仅校验 `summary` 字段：
- `summary`：必填，单行纯文本，不超过 200 个字符，概括页面当前的最新认识或状态。更新页面时若核心结论或进度位置发生变化，同步更新 `summary`，保持条件保真并移除已过时的旧信息。
- 其他自定义字段（如 Obsidian 使用的 `tags`、`aliases`）在服务端读写时原样保留。

### 正文组织约定

服务端不强制校验 Markdown 正文的小节结构。模型按 [`references/memory-format.md`](../../skills/cairn/references/memory-format.md) 的格式约定组织正文，内容取舍与行动效力遵循[记忆](../design/memory.md)中的规则：
- **掌握状态（`state/mastery/`）**：综合历次观察说明当前能力边界、核心依据（表现发生日期、任务、支持条件、信息来源）及影响选择时的确信度说明，新表现超越早期局限时覆盖旧快照。
- **学习特征（`state/traits/`）**：记录跨内容可迁移的认知与协作归纳及已观察到的项目与日期范围（出现过反例时注明例外）。
- **学习进度（`state/progress/`）**：包含材料与工作区定位信息（默认材料通道相对路径、逻辑目录相对路径或外部链接）、进展概况、当前工作状态（停留位置、已发生的尝试结果、标明来源与暂定性质的当前分析认识、正在开展的步骤）、学习者要求保留的备忘及已确定的下一步安排；不设“未决问题”或“模型候选建议”固定栏目。
- **学习者设定（`settings/`）**：`general.md` 分节书写个人背景自述、长期方向与每轮对话均需遵循的高频教学约定及工作流简短入口指针；具体项目的目标与专门分工写入 `projects/<项目>.md`；外部工具协作细则、笔记重点原则与输出格式模板按实际复杂度拆入按需设定子目录并通过页面标识或双链引用串联。纳入 git 的页面中统一使用逻辑目录名加相对路径引用外部位置，不硬编码盘符或挂载点。

### 双链 `[[页面名]]`

- 采用与 Obsidian 一致的语法：`[[页面名]]`、`[[页面名|显示文字]]` 或 `[[页面名#标题]]` 均解析为指向目标页面（设定页在 Obsidian 与跨目录引用中可写作 `[[settings/workflows/note-guide]]`）；代码块与行内反引号中的内容不解析。
- 双链用于建立页面间的语义关联（供 `start_session` 从进度页召回相关掌握状态摘要、供 `get_related_pages` 检索关联上下文）以及供人在 Obsidian 中点击跳转。
- 双链允许指向尚未建立的状态页面；调用 `move_page` 或带 `redirect_to` 的 `remove_page` 时，服务端自动同步改写所有页面与记录中的目标双链。

### 学习记录（`records/`）

文件位于 `records/YYYY-MM-DD.md`，顶部一级标题为 `# YYYY-MM-DD`。每条记录为一个无序列表项，固定由服务端拼装前三个元数据字段：

```markdown
- 20:12 `cs336` `7f3k2a` 学习者决定本项目核心模块先自行编写，受阻时先给方向提示。
- 22:05 `-` `-` 学习者计划下月结合工作需求阅读分布式通信源码。
```

- 三个前置字段依次为 `HH:MM`（服务端配置时区）、`` `<学习项目>` ``、`` `<6位对话标记>` ``；缺失项固定写作 `` `-` ``。正文以第三人称记述，跨行内容后续行缩进两个空格。
- 记录只追加不删改；发现过往记录有误时，追加一条指明原记录日期与时间的更正条目（如 `更正 2026-11-14 20:58 的记录：……`）。

### 时间信息

页面内不手写维护元数据时间戳。服务端从每个状态页面文件的 git 提交历史（启用重命名追踪 `--follow`）中统计实际内容变更提交（包含 `write_page`、`edit_page` 及学习者直接修改页面内容的提交，排除 `move_page`、`remove_page` 的重命名与双链改写提交），计算三项时间信息随工具返回：**首次创建日期、最近更新日期、累计更新天数**（其作为粗筛索引的定位见[记忆](../design/memory.md#页面链接索引与时间信息)）。多设备部署多个数据仓库副本时，各端服务端统一配置相同时区。

### 本机目录索引（`paths.local.toml`）

数据仓库根目录下的 `paths.local.toml` 由 `.gitignore` 忽略，用于在本机或服务器本地维护逻辑目录名到实际文件系统路径及读写权限边界的映射；`templates/data/paths.example.toml` 提供不含本机路径的模板：

```toml
# 本机外部目录索引（列入 .gitignore，不纳入 git）

[roots.materials]
path = "G:/My Drive/Study/Materials"
access = "read"
description = "课程讲义、教材与论文目录（本地网盘挂载目录或服务器 rclone 挂载目录）"

[roots.notes]
path = "D:/Obsidian/MainVault"
access = "read-write"
description = "个人独立笔记库与阶段梳理成稿导出目录"

[roots.workspaces]
path = "D:/Courses"
access = "read-write"
description = "课程作业与源码工程默认父目录"
```

- 字段约束：每个条目位于 `[roots.<逻辑名>]` 下，包含必填的 `path`（当前机器路径）、`access`（`read` 或 `read-write`）与可选的 `description`。不在统一父目录下的独立项目可单独登记（如 `[roots."project.vllm"]`）。
- 作用域：本地 `stdio` 模式下，`start_session` 返回该映射供本地代理跨目录寻址并限制外部写入范围；服务端未单独设置 `SOURCES_DIR` 时自动复用 `roots.materials.path` 作为默认材料通道根目录。远程 `HTTP` 模式仅在服务端内部使用 `roots.materials.path`，不向网页端暴露宿主机路径。

- **单条实例追踪优于静态结构总览**：接触陌生复杂机制或代码时，先给定一个具体输入并沿处理链路追踪状态变化，比先介绍模块职责分层更容易建立准确认识。依据：2026-11 在 `cs336` 分词器与注意力模块中两次对照观察有效。

## 外部材料与默认材料通道

学习材料的存放与读取支持自由组织，同时提供一套免自建同步服务的默认配置：
- **默认推荐配置（网盘挂载 + 默认材料通道）**：将课程 PDF、教材与论文放入云盘（如 Google Drive），本机通过桌面客户端挂载为本地目录，远程服务器通过 `rclone mount` 挂载同一目录，并在各自的 `paths.local.toml` 中将其登记为 `roots.materials`（不再依赖自建维护 Syncthing）。本地代理直接读取本机挂载路径，网页端通过 `list_sources` 与 `read_source` 查看 PDF 书签目录并按页截取原件读取。
- **自定义外部工作流**：项目也可完全不使用服务端默认材料通道（例如直接在本地代码仓库工作、在聊天框上传单篇文档或使用外部连接器）。当进度页登记了默认材料通道下的相对路径且对应目录存在时，`start_session` 自动报告新增、更新或缺失的材料文件；外部逻辑路径（如 `workspaces:`、`notes:`）不触发缺失报警。

## 格式版本

数据仓库根目录的 `FORMAT_VERSION` 标识存储格式版本（v1 为 `1`，基础版为 `2`）。基础版直接由新模板初始化数据仓库，不提供 v1 数据的转换脚本；未来基础版发生破坏性格式调整时，递增版本号并随系统仓库附带迁移脚本。

### 与 v1 目录的对照

| v1 目录/文件 | 基础版对应位置 |
|---|---|
| `profile/` | `settings/general.md`、`settings/projects/` 及按需设定子目录 |
| `state/concepts.md` | `state/mastery/` 与 `state/traits/` 下的独立页面 |
| `state/progress/` | `state/progress/` |
| `state/log/` | `records/YYYY-MM-DD.md` |
| `sources/`（固定由 Syncthing 同步） | 独立为可选材料目录（由 `SOURCES_DIR` 或 `paths.local.toml` 的 `roots.materials` 指定，支持网盘挂载或外部工作流） |
