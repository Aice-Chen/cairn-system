# 数据仓库

本文说明个人数据仓库的目录结构、文件与格式规范、完整示例以及与系统仓库的关系。数据仓库是长期记忆的存储实现；各部分记忆的价值边界、语义与更新规则见[记忆](../design/memory.md)。

## 与系统仓库的分离

Cairn 使用两个相互独立的 git 仓库：

| 仓库 | 保存内容 | 所有者 | 可见性 |
|---|---|---|---|
| 系统仓库 | 插件配置、技能（指引与格式参考）、MCP 服务端源码、初始化模板、设计文档 | 项目维护者 | 公开，不含任何个人数据 |
| 数据仓库 | 一位学习者的设定、学习状态与学习记录（`sources/` 存放材料但不纳入 git） | 学习者本人 | 私有 |

数据仓库由系统仓库中的 `templates/data/` 初始化生成。两个仓库在 git 历史上完全独立：日常升级系统仓库或插件不会改动数据仓库中的文件；仅当记忆底层格式版本升级时才通过迁移脚本处理。

## 目录结构

```text
<数据仓库>/
├── settings/               学习者设定
│   ├── general.md            通用设定，每次 start_session 加载全文
│   └── projects/             项目设定，每个学习项目一页（可选），对应项目时加载全文
├── state/                  学习状态
│   ├── progress/             学习进度，每个学习项目一页
│   ├── mastery/              掌握状态，按可复用概念、机制或能力建页（可建子目录归类）
│   └── traits/               学习特征，跨内容可检验的辅导假设
├── records/                学习记录，按日期归档（YYYY-MM-DD.md），只追加
├── sources/                学习材料与作品，每个学习项目一个子目录（.gitignore 忽略）
└── FORMAT_VERSION          记忆格式版本号（基础版为 2）
```

结构说明：
- **学习项目标识符**：代表一门课程、一本书、一个代码库或一个实践专题（对应 v1 中的“资源”），同时用作 `state/progress/<项目>.md`、`settings/projects/<项目>.md` 和 `sources/<项目>/` 的名称。
- **`settings/` 的纯粹性**：只存放学习者的个人背景自述、目标与协作约定；通用教学原则随插件技能提供，后续笔记模板随笔记扩展模块另行设计。
- **`state/` 的子目录**：固定划分为 `progress/`、`mastery/`、`traits/` 三类。`mastery/` 内部可由模型按领域建立子目录用于归组，但页面仍以文件名在 `state/` 内全局唯一标识。

## 记忆格式规范

本节定义服务端强制检查的格式规则，以及由 [`references/memory-format.md`](../../skills/cairn/references/memory-format.md) 传达给模型的正文组织约定。

### 名称规则

页面名称即去掉 `.md` 后缀的文件名：
- **学习项目名称**：仅由小写英文字母、数字和连字符 `-` 组成（如 `cs336`、`vllm-scheduler`）。
- **学习状态页面名称**：可使用中文、英文字母、数字、空格和圆括号，长度不超过 80 个字符，禁止包含文件系统与双链特殊字符：`/`、`\`、`:`、`*`、`?`、`"`、`<`、`>`、`|`、`#`、`^`、`[`、`]`。名称在整个 `state/` 目录下不区分大小写唯一。`mastery/` 页面命名优先采用**可跨项目复用的概念、机制或能力名称**（如 `缩放点积注意力`、`内存合并访问`），避免采用一次性任务标题（如“作业一第三题”）。
- **设定页面标识**：在工具调用中固定使用 `general` 或 `projects/<学习项目>`。

### frontmatter

每个设定页面与状态页面顶部均包含 YAML frontmatter，服务端仅校验 `summary` 字段：
- `summary`：必填，单行纯文本，不超过 200 个字符，概括页面当前的最新认识或状态。更新页面时若核心结论或进度位置发生变化，同步更新 `summary`，保持条件保真并移除已过时的旧信息。
- 其他自定义字段（如 Obsidian 使用的 `tags`、`aliases`）在服务端读写时原样保留。

### 正文组织约定

服务端不强制校验 Markdown 正文的小节结构，模型按以下职责约定组织正文：
- **掌握状态（`state/mastery/`）**：综合历次观察说明当前在什么条件下能做到什么，保留支撑当前判断的核心依据（日期、具体任务、实际获得的支持条件、直接观察还是事后自述），并在影响后续选择时注明确信度来源。新表现超越早期局限时直接合成覆盖旧快照，不堆砌历史流水账；不列尚未观察的通用待办清单；与当前目标直接相关的明确差距注明对应目标。
- **学习特征（`state/traits/`）**：记录跨内容可检验的辅导工作假设（有效的认知切入方式、跨主题反复出现的执行盲区、自评校准倾向），每条写明支撑该假设的观察范围（涉及的项目与日期）及已知例外。
- **学习进度（`state/progress/`）**：包含材料登记、大纲或里程碑进展、当前停留位置与未完工作（含悬而未决的问题与**已尝试但排除的方案**），以及学习者已确定的下一步安排。不设“模型候选建议”栏目，未经学习者要求备忘的推测性教学建议不写入进度页。
- **学习者设定（`settings/`）**：将背景自述与目标、持续协作约定分节书写；具体适用条件或期限直接写在对应条目中。

### 双链 `[[页面名]]`

- 采用与 Obsidian 一致的语法：`[[页面名]]`、`[[页面名|显示文字]]` 或 `[[页面名#标题]]` 均解析为指向目标状态页面；代码块与行内反引号中的内容不解析。
- 双链用于建立页面间的语义关联（供 `start_session` 从进度页召回相关掌握状态摘要、供 `get_related_pages` 检索关联上下文）以及供人在 Obsidian 中点击跳转。
- 双链允许指向尚未建立的状态页面；调用 `move_page` 或带 `redirect_to` 的 `remove_page` 时，服务端自动同步改写所有页面与记录中的目标双链。

### 学习记录（`records/`）

文件位于 `records/YYYY-MM-DD.md`，顶部一级标题为 `# YYYY-MM-DD`。每条记录为一个无序列表项，固定由服务端拼装前三个元数据字段：

```markdown
- 20:12 `cs336` `7f3k2a` 学习者决定本项目核心模块先自行编写，受阻时先给方向提示。
- 22:05 `-` `-` 学习者计划下月结合工作需求阅读分布式通信源码。
```

- 三个前置字段依次为 `HH:MM`（服务端配置时区）、`` `<学习项目>` ``、`` `<6位对话标记>` ``；缺失项固定写作 `` `-` ``。正文以第三人称记述，跨行内容后续行缩进两个空格。
- 记录只追加不删改；发现过往记录有误时，追加一条指明原记录日期与时间的更正条目（如 `更正 2026-11-14 20:58 的记录：……`）。

### 时间信息

页面内不手写维护元数据时间戳。服务端直接从每个状态页面文件自身的 **git 提交历史（启用重命名追踪）** 读取并计算三项时间信息随工具返回：**首次创建日期、最近更新日期、累计更新天数**。多设备部署多个数据仓库副本时，各端服务端统一配置相同时区。

### 1. 通用设定 `settings/general.md`

```markdown

---

## 背景自述

有两年后端服务开发经验，熟悉 Python 和 Go，写过基础并发程序；大学学过线性代数与概率论，矩阵求导和张量高维变换生疏。

## 长期方向

深入理解大语言模型训练与推理系统的底层机制，具备阅读主流推理框架源码、定位性能瓶颈并修改核心模块的能力。

## 通用协作约定

- 引入抽象概念或公式前，先给一个最小的具体数值或形状实例。
- 当我明确说“直接给结论”时，省略引导提问，直接给出完整分析与实现。
```

# 缩放点积注意力

关联页面：[[多头注意力]]、[[因果掩码]]、[[PyTorch广播机制]]。

### 4. 学习特征 `state/traits/认知与实现习惯.md`（跨内容可检验的辅导假设）

```markdown
---
summary: 理解复杂系统倾向从单条数据流追踪切入；多维张量或状态并发编码前若先显式写出形状/状态不变量，排错效率显著提高。
---

# 认知与实现习惯

- **单条数据流追踪优于静态模块总览**：接触陌生复杂代码或架构时，先给定一个具体输入并沿调用链追踪其状态与数据结构变化，比先介绍各模块职责分层更容易建立准确直觉。依据：2026-11 在 `cs336` 分词器与注意力模块中两次对照观察有效；例外：尚无，待后续系统源码项目中继续检验。
- **动手编码前易略过显式不变量核对**：直接开始写多维张量变换或边界切片时容易凭直觉写反维度，但一旦提示先把每一步的输入输出形状写成注释，往往能立刻自行发现问题。依据：2026-11-14 与 2026-11-16 两次实现观察；11-20 已开始主动先列形状。
```

## 学习材料的管理

学习材料存放在 `sources/<学习项目>/` 下，仅放入模型可直接读取的文件（Markdown、代码、文本、PDF 等），目录由 `.gitignore` 排除，跨设备可通过 Syncthing 等文件同步工具维护。

进度页在基本信息中以相对于 `sources/<学习项目>/` 的路径登记材料（单个文件如 `lectures/lec04.pdf`，整个目录以 `/` 结尾如 `assignment1-basics/`）。`start_session` 据此比对磁盘文件，自动报告未登记的新材料、修改时间晚于进度页的已更新材料以及登记后缺失的路径。学习者的梳理成稿或笔记若放入该目录，模型同样可按材料读取。

## 格式版本

数据仓库根目录的 `FORMAT_VERSION` 标识存储格式版本（v1 为 `1`，基础版为 `2`）。基础版直接由新模板初始化数据仓库，不提供 v1 数据的转换脚本；未来基础版发生破坏性格式调整时，递增版本号并随系统仓库附带迁移脚本。

### 与 v1 目录的对照

| v1 目录/文件 | 基础版对应位置 |
|---|---|
| `profile/` | `settings/general.md` 与 `settings/projects/` |
| `state/concepts.md` | `state/mastery/` 与 `state/traits/` 下的独立页面 |
| `state/progress/` | `state/progress/` |
| `state/log/` | `records/YYYY-MM-DD.md` |
| `sources/` | `sources/`（保持不变） |
