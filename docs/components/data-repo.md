# 数据仓库

本文说明数据仓库的目录结构和文件格式。数据仓库是记忆的实现形式；记忆的类别、效力、页面和更新方式见[记忆](../design/memory.md)。各部分的确认状态见[议题与决策](../decisions.md)。

## 与系统仓库的关系

Cairn 使用两个相互独立的 git 仓库。

| 仓库 | 内容 | 所有者 | 可见性 |
|---|---|---|---|
| 系统仓库 | 插件（技能、MCP 连接声明）、服务端源码、数据仓库模板、文档 | 项目 | 公开，不含任何个人数据 |
| 数据仓库 | 一位学习者的记忆 | 学习者 | 私有 |

数据仓库由系统仓库中的模板 `templates/data/` 建立。两个仓库之间没有合并关系：插件升级不改动数据仓库的内容，只有记忆格式变更时才需要迁移。

内容归入哪个仓库，取决于它是否依赖某位学习者的个人信息。可跨学习者复用的指引、学习方法和文档属于系统仓库，方法可以具有具体的适用条件；一位学习者的设定、学习状态和学习记录属于其数据仓库。

## 目录结构

```text
<数据仓库>/
├── settings/               学习者设定
│   ├── general.md            通用设定，每次加载
│   └── projects/             项目设定，每个学习项目一页（可选）
├── state/                  学习状态
│   ├── progress/             学习进度，每个学习项目一页
│   ├── mastery/              掌握状态，页面的粒度和子目录由模型决定
│   └── traits/               学习特征
├── records/                学习记录，按日期归档，每天一个文件
├── sources/                学习材料，每个学习项目一个目录，不纳入 git
└── FORMAT_VERSION          记忆格式的版本号
```

通用背景、跨项目目标和协作约定写入 `settings/general.md`；某个项目的目标和协作约定写入 `settings/projects/<学习项目>.md`。任务、情境和时间条件直接写在相应内容中，按其适用于多个项目还是某个项目选择位置。加载时提供通用设定和当前项目设定的全文，具体返回见[服务端](server.md#start_session-的返回)。

设定页保存当前有效的陈述、目标和持续协作约定。具体安排和候选提议写入项目进度，说明哪些已经开展、哪些尚在考虑；模型的安排随当前目标和进展调整。过去的选择及其变更原因保存在学习记录中。目标或约定改变后，设定页呈现新的有效内容，历史通过记录和 git 保存。

有三点说明。

- 学习项目围绕相互关联的目标、材料和任务组织，可以以课程、书籍、代码库或实践项目为载体，对应 v1 中的“资源”。每个学习项目在 `state/progress/` 下有一个进度页，在 `sources/` 下有一个同名的材料目录。
- `settings/` 包含学习者自己的陈述和约定。通用教学依据随系统提供，基础版技能包括指引正文和记忆格式参考。笔记模板随笔记生成模块设计。
- `state/` 按学习状态的种类分为三个子目录。`mastery/` 和 `traits/` 内部的页面划分不作规定。

## 记忆格式

本节规定页面、链接和学习记录的格式。其中供模型使用的名称、链接和正文约定集中在技能的 `references/memory-format.md` 中，当前正文见[记忆格式参考草稿](../drafts/cairn/references/memory-format.md)。

### 名称

页面以名称标识，名称即去掉 `.md` 的文件名。

- **学习项目**的名称由小写字母、数字和连字符组成，例如 `cs336`。它同时是该项目的进度页、材料目录和项目设定的名称。
- **学习状态页面**的名称可以使用任何文字，包括中文、空格和括号，不超过 80 个字符，不含在文件名或链接中有特殊含义的字符：`/`、`\`、`:`、`*`、`?`、`"`、`<`、`>`、`|`、`#`、`^`、`[`、`]`。名称在 `state/` 内唯一，不区分大小写；子目录只用于归类。
- **设定页面**按适用范围组织：通用设定为 `general`，项目设定以学习项目的名称命名。

### frontmatter

frontmatter 中只定义 `summary` 一个字段：必填，一行，不超过 200 个字符，概括页面的当前内容，新建和重写页面时提供。其他字段原样保留，服务端不作解释，例如 Obsidian 的 `tags`。

### 正文

正文按内容组织，由模型选择便于理解、引用和更新的段落或标题。掌握状态描述已有表现支持的能力，保留解释这一判断所需的来源、任务和支持条件；影响判断使用的具体限制随相关内容说明。进度页概括项目位置、实际进展和当前安排，材料路径、大纲或里程碑按需要列出。已经开展的安排、学习者选择的后续计划和模型提出的候选建议应能从文字中辨认。

这些写作约定由技能的记忆格式参考提供。服务端负责页面和记录的格式规则，正文的教学含义由模型解释。

### 链接

- 链接写作 `[[页面名]]`，与 Obsidian 的链接语法一致，指向学习状态页面。带显示文字的 `[[页面名|显示文字]]` 和指向标题的 `[[页面名#标题]]` 同样视为指向该页面。
- 代码块和行内代码中的内容不解析为链接。
- 链接可以指向尚不存在的页面。页面建立后，此前的学习记录中指向它的链接计入它的时间信息。

### 学习记录

学习记录的文件为 `records/YYYY-MM-DD.md`，每天一个，以一级标题写明日期。每条记录是一个列表项，依次为时间、学习项目、对话标记和内容：

```markdown
# 2026-11-14

- 20:12 `cs336` `7f3k2a` 学习者在一次维度提示后，自行修正了 [[缩放点积注意力]] 实现中的掩码广播错误。
- 22:05 `-` `-` 学习者表示下周开始学习操作系统。
```

- 时间、学习项目和对话标记由服务端写入，位置固定；缺少的一项写作 `-`。内容可以跨行，后续各行缩进两个空格。
- 对话标记由 6 个小写字母和数字组成。服务端发放的标记原样写入；客户端或插件提供的对话标识，写入由它计算出的 6 个字符的摘要。由摘要不能还原原来的标识，原来的标识也不保存。
- 学习记录只追加。唯一的例外是页面重命名或合并时，服务端改写记录中指向该页面的链接；时间、学习项目、对话标记和其余的文字不变。

### 时间

页面的首次记录、最近涉及、涉及天数和最近更新由服务端计算，随工具结果提供。它们反映记录、引用和文件更新的时间，具体教学含义结合相关内容解释。正文在需要时保留表现实际发生的时间；记录事后自述时，写明信息来自学习者报告，并在已知时注明事件时间。

学习记录的归档日期和条目时间使用服务端配置的时区，由服务端写入。数据仓库有多个副本时（见[插件](plugin.md)中“运行方式”），各副本的服务端使用同一时区。

## 示例

以下虚构示例展示设定、能力判断与项目进度的不同用途。正文的组织随内容确定。

项目设定 `settings/projects/cs336.md`：

```markdown
---
summary: CS336 的目标与约定：借助文档实现并解释主要模块，核心实现由学习者完成。
---

# cs336

能够借助框架文档实现课程中的主要模块，解释关键设计，并用测试检查实现。核心逻辑由我完成。

环境配置和绘图可以交给模型。实现核心逻辑遇到困难时，先提示方向；我要求示范时，完整展示相关局部。
```

掌握状态页面 `state/mastery/缩放点积注意力.md`，按实际表现描述能力和所获支持：

```markdown
---
summary: 能够说明缩放点积注意力的计算过程和缩放因子的作用；在一次维度提示后自行修正了掩码广播错误。
---

# 缩放点积注意力

所属学习项目：[[cs336]]。相关页面：[[多头注意力]]。

能够说明 Q、K、V 的含义、计算过程和除以 √d_k 的原因。依据是 2026-11-12 的无提示解释，以及 2026-11-14 讨论多头注意力时的正确运用。

2026-11-14 的实现中出现掩码广播错误。模型提示检查掩码与注意力分数的形状后，学习者自行修正，体现了在这一提示支持下检查和调整维度的能力。
```

进度页 `state/progress/cs336.md`：

```markdown
---
summary: CS336 作业 1 的注意力部分进行中；当前先练习张量变形，再继续实现。
---

# cs336

材料：`lectures/`、`assignment1-basics/`。当前目标与协作约定见本项目设定。

讲座 1 至 3、分词器已完成。作业 1 进行到注意力部分，[[缩放点积注意力]] 的掩码广播错误已在一次提示后修正。

学习者选择先练习张量变形，再继续带掩码注意力的实现；目前正在进行张量变形练习。模型建议后续进入 Transformer 块，作为下一阶段的候选安排。
```

## 学习材料

学习材料放在 `sources/<学习项目>/` 下，只放模型可以直接读取的文件，项目内部可以自由建立子目录。材料由学习者放入，或由工具下载公开的文件。它不纳入 git，多台设备之间的同步使用 git 以外的方式。

一个学习项目使用哪些材料，写在它的进度页中。服务端在加载记忆时，报告材料目录中尚未写入进度页的新材料、修改时间晚于进度页的材料，以及写入了进度页而已不存在的路径。

学习者的作品，例如对一个主题的梳理成稿，也可以放在这里，模型像读取学习材料一样读取它。

## 格式版本

记忆格式的版本号记录在 `FORMAT_VERSION` 中。v1 的格式版本为 1，基础版为 2。服务端启动时检查版本号，与它支持的版本不一致时拒绝启动。格式变更时提高版本号，并在同一次变更中提供迁移说明或迁移脚本。基础版的数据仓库由模板新建，不提供从 v1 格式的迁移。

## 与 v1 数据目录的对应

下表供在 v1 服务端的基础上修改时参考，数据不作转换。

| v1 | 基础版 |
|---|---|
| `profile/` | `settings/` |
| `state/concepts.md` | `state/mastery/` 下的页面 |
| `state/progress/` | `state/progress/` |
| `state/log/` | `records/` |
| `sources/` | `sources/`，不变 |
