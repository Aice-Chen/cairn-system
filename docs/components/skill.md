# 技能

本文说明技能的目录结构与加载时机、设计文档与指引正文的分工，以及指引的编写约定与检验方式。技能是指引的实现形式：指引正文为 [`skills/cairn/SKILL.md`](../../skills/cairn/SKILL.md)，记忆格式说明为 [`skills/cairn/references/memory-format.md`](../../skills/cairn/references/memory-format.md)。各项内容的确认状态见[议题与决策](../decisions.md)。

## 组成与加载

```text
skills/cairn/
├── SKILL.md                    技能描述与指引正文
└── references/
    └── memory-format.md        记忆格式说明
```

| 组成部分 | 内容 | 加载时机 |
|---|---|---|
| 技能描述（frontmatter） | 何时选用本技能：学习者开始或继续学习、围绕材料或代码开展分析与练习、查询进度或掌握状态、调整目标或辅导约定时 | 始终在客户端上下文中 |
| 指引正文 | 角色与目标、开始与决定权、教学判断、教学依据、记忆的使用 | 技能被选用时加载 |
| 参考文件 | 记忆格式说明；后续按需加入的跨学习者专项学习方法 | 模型首次写入或需要查阅时按需读取 |

内容按加载频率分配：每次开展辅导都需要遵循的角色定位、判断维度和记忆原则放在指引正文；目录命名、摘要长度、各页面具体组织与记录语法放在参考文件，减少常驻上下文负担。基础版不在插件 `references/` 下预置通用的学习方法参考文件（见[辅导](../design/tutoring.md#具体做法与学习方法的演进)）；学习者个人的外部工作流约定与笔记输出模板保存在个人数据仓库的 `settings/` 按需设定页中。

## 设计文档与指引的分工

设计文档与指引面向不同读者，服务于不同目的，内容详略因此分开维护。

| 维度 | 设计文档（`docs/`） | 指引（`skills/cairn/`） |
|---|---|---|
| 读者 | 设计者、开发者、维护者 | 开展辅导的旗舰模型 |
| 内容 | 产品目标、概念定义、决策背景与替代方案取舍、研究依据及其适用限度、解释性案例 | 模型在运行中需要把握的角色目标、关键权衡维度、客观判断条件和系统读写约定 |
| 详略 | 完整展开理由与边界，供后续评审和修改时核对原意 | 高信息密度：省略文献引证与方案比较，但每一条判断依据都写清条件与逻辑关系 |
| 维护方式 | 按[议题与决策](../decisions.md)登记并更新 | 随设计层的确认结论同步修订 |

两者的对应关系如下：
- 指引中的每一项要求在设计文档中都有明确出处；仅服务于维护论证的内容（如设计哲学、历史方案对比、文献限度）留在设计层，不进入指引。
- 指引正文各小节与设计文档的对应关系如下表所示。

| 指引正文小节 | 设计文档出处 |
|---|---|
| 一、角色与目标 | [目标、边界与设计哲学](../design/goals-and-principles.md)中的“产品目标”；[学习模型](../design/learning-model.md)中的“目标” |
| 二、开始学习与决定权 | [学习模型](../design/learning-model.md)中的“先推进、后收敛”与“决定权划分”；[辅导](../design/tutoring.md)中的“材料条件、任务要求与工作区说明冲突”及“学习项目的推进过程” |
| 三、教学判断 | [学习模型](../design/learning-model.md)中的“模型的整体关系”至“互动中的假设探测与补充活动权衡”；[辅导](../design/tutoring.md)中的“在互动中探测状态与试探辅导方式” |
| 四、教学依据 | [辅导](../design/tutoring.md)中的“教学依据”与“借助 AI 完成任务与能力的形成” |
| 五、记忆的使用 | [记忆](../design/memory.md)全文 |
| 记忆格式参考 | [数据仓库](data-repo.md)中的“目录结构”与“记忆格式” |

## 指引的编写约定

指引面向旗舰模型编写，遵循[目标、边界与设计哲学](../design/goals-and-principles.md)中“模型为主”与“有边界的理论依据”两条立场，采用以下约定：

- **以角色定位、目标与权衡维度引导判断。** 通用对话助手默认偏向单轮给出完整答案、顺从表面请求并尽快结束当前任务。指引通过明确长期导师职责、多元目标形态以及需要权衡的关键条件，引导模型围绕学习目标开展教学判断：既避免写没有信息增量的空泛同义反复（如仅写“根据具体情况调整”），也避免用单一场景的窄面警句（如只针对听课走神的局部提醒）替代通用关系。
- **写通用判断条件，不设离散分类或水平标签预设。** 不把学习划分为互斥类型并绑定固定步骤，也不按“新手 / 熟练者”身份标签预设处理套路；面对不同材料、任务和先备基础时，指出需要关注的通用条件（如依据的可核验性、反馈来源与过程可见性、结构复杂度与主次关系），由模型实时权衡。
- **教学依据陈述完整因果条件。** 每条教学依据写明何种处理方式有助于理解、保持或校准认识，以及背后的原因和适用前提，使模型在未枚举的具体情境中能够自行推演。
- **系统特有契约界定清楚。** 单靠“担任好导师”无法自动推出的系统规则（如决定权协商阈值、推理归属边界、状态更新时的淘汰重选、基于 git 历史的时间机制与工具调用时机）明确写出。
- **否定性限制从严、示例从少。** 否定性规定仅用于实际使用中反复出现的问题或当前系统的客观限制。示例具有较强的模仿诱导性，仅在抽象陈述难以厘清边界时少量使用，不使用正反对比式反例。
- **专业、平实、厂商中立。** 使用克制的书面表述，不出现夸张或口语化措辞，不绑定特定客户端的专有术语，使同一份技能文本可在不同客户端复用。

## 指引的检验

指引在较大修订后先通过场景走查核验逻辑闭环，再进入实际学习试用。走查覆盖三类典型情境：
- **CS336 作业实现与调试**：目标是在查阅文档条件下完成核心模块并解释关键设计；学习者在局部提示后定位并修正了张量形状错误。
- **vLLM 调度器源码分析**：目标是在有限时间内理清请求调度的主干状态流转与设计取舍。
- **教材或论文学习**：起初希望快速了解整体脉络，中途转为准备独立推导核心公式。

在每个情境中进一步改变一项条件（可用时间缩短、目标形态转换、先备知识已存在于其他项目的状态页中、对话中途暂停后续接，或要求按个人模板整理阶段笔记），重点检查：
- 开场是否直接回应具体问题而非先行询问建档；
- 能否通过掌握状态全量名称清单识别跨项目的已有概念页面；
- 涉及外部工作流或整理阶段笔记时，能否根据按需设定摘要调用 `read_pages` 读取对应规范，并遵守 `paths.local.toml` 声明的外部写入边界；
- 相同结果在不同支持条件（含模型顺势补全推理）下，写入掌握状态的范围是否如实；
- 暂停续接时，进度页能否恢复当前工作分析认识与备忘，同时未在各类页面中生成面向未来的验证计划或未经选定的待办条目；
- 更新状态页与摘要时，是否主动淘汰了已被超越的旧细节；
- 已有信息足以推进时，模型是否直接推进而非额外插入测验。

场景走查作为修订时的检验手段，最终效果以长期真实学习试用为准。
