# 技能

本文说明技能的组成与加载方式、设计文档与指引的分工，以及指引的写法和检验。技能是指引的实现形式：指引正文的草稿是 [`skills/cairn/SKILL.md`](../../skills/cairn/SKILL.md)，记忆格式说明是 [`skills/cairn/references/memory-format.md`](../../skills/cairn/references/memory-format.md)。各项内容的确认状态见[议题与决策](../decisions.md)。

## 组成与加载

```text
skills/cairn/
├── SKILL.md                    技能描述和指引正文
└── references/
    └── memory-format.md        记忆格式说明
```

| 部分 | 内容 | 加载时机 |
|---|---|---|
| 技能描述 | 何时使用本技能：学习者开始或继续学习、询问学习进度或掌握情况、调整目标或辅导方式时 | 始终在上下文中 |
| 指引正文 | 角色与目标、教学判断、教学依据、学习者的决定、记忆的使用 | 技能被选用时 |
| 参考文件 | 记忆格式说明；之后加入的学习方法 | 模型按需读取 |

内容按加载时机分配：每次辅导都需要的内容放在指引正文，只在特定情形下需要的内容放在参考文件。基础版没有学习方法的参考文件（见[辅导](../design/tutoring.md)中的“具体做法与学习方法”）。

## 设计文档与指引的分工

设计文档和指引面向不同的读者，承担不同的工作，详略因此不同。

| | 设计文档 | 指引 |
|---|---|---|
| 读者 | 设计者、开发者、贡献者 | 进行辅导的模型 |
| 内容 | 目标、概念、决定及其理由，考虑过而没有采用的方案，研究依据及其限度，例子 | 模型在辅导中需要持续遵循的目标、判断方式、教学依据和约定 |
| 详略 | 充分：每项决定都说明理由和取舍，便于之后修改时理解原意 | 精简：只写会改变模型行为的内容，但每项陈述完整 |
| 修改 | 按[议题与决策](../decisions.md)中的方式，确认后修改 | 随设计的修改同步更新 |

两者的关系如下：
- 指引中的每一项陈述，都能在设计文档中找到出处；设计文档中的内容不一定进入指引。
- 指引不包含设计哲学、考虑过的方案、文献，以及面向设计者的例子。
- 教学依据在指引中写成完整的陈述：学习在什么条件下发生，对教学有什么含义。去掉文献，保留含义。

指引正文各部分在设计文档中的出处如下。

| 指引正文的部分 | 出处 |
|---|---|
| 一、角色与目标 | [目标、边界与设计哲学](../design/goals-and-principles.md)中的“产品目标”；[共同学习模型](../design/learning-model.md)中的“目标” |
| 二、教学判断 | [共同学习模型](../design/learning-model.md)中从“模型的结构”到“何时安排补充的活动”各节 |
| 三、教学依据 | [辅导](../design/tutoring.md)中的“教学依据”和“借助 AI 完成任务与能力的形成” |
| 四、学习者的决定 | [共同学习模型](../design/learning-model.md)中的“决定权的划分”；[辅导](../design/tutoring.md)中的“学习材料与任务要求” |
| 五、记忆的使用 | [记忆](../design/memory.md)；[辅导](../design/tutoring.md)中的“学习项目的过程” |
| 记忆格式说明 | [数据仓库](data-repo.md)中的“记忆格式” |

## 指引的写法

指引的写法依据设计哲学中“模型为主、目标导向”和“有理论依据”两条立场，有以下约定。
- **陈述依据，不规定做法。** 写明目标、条件、判断的依据和需要权衡的因素，具体做法由模型判断。
- **教学依据写完整。** 每条教学依据写明学习在什么条件下发生、对教学有什么含义，使模型能够在依据没有覆盖的情形下自行推理。
- **不按水平预设。** 依据学习者在具体内容上的知识和表现选择支持，不针对不同水平的学习者预设处理方式；对学习者水平的描述只作为背景。
- **否定性条目从严。** 只在两种情况下写入：一是实际使用中反复出现的不当做法，二是由当前系统的限制决定的不可行做法。每一条写明它所针对的现象。
- **示例从少。** 示例只用于无法直接陈述的判断，不使用对比式的反面示例。示例是很强的信号，会被模仿：此前的记忆格式示例中，“尚待观察”在摘要、判断和进度页中反复出现，模型也会据此在写入中大量使用这一表述。
- **书面、中立的表述。** 使用书面的专业表述，不依赖特定厂商的术语，使同一份技能可以用于不同的客户端。
- **写项目特有的内容。** 写项目特有的目标、取舍和优先级；通用的教学知识，只在会改变模型的决策时写入。

## 指引的检验

指引是否有效，最终要在使用中检验。每次较大的修改之后，先用场景走查检验一次。走查使用三个场景：
- **CS336 作业 1。** 目标是能够实现并调试其中的模块，允许查阅文档。学习者在模型解释局部关系后完成实现，在提示后修正了一个错误。
- **阅读 vLLM 的调度器。** 目标是在有限的时间内理解主要流程和设计理由。
- **阅读一章教材。** 起初只想建立概览，之后改为准备独立解题。

每个场景再改变一项条件：时间更少，目标更深，已有的知识更充分，或出现了新的证据。然后检查以下几点：
- 指引能否说明安排为什么改变，或为什么保持不变；
- 记忆中会写下什么；
- 同样的任务结果，在不同的支持条件下支持什么判断；
- 一项旧的建议进入新的对话后，处于什么地位；
- 已有信息足以推进时，模型是否直接推进；
- 学习者调整投入或结束目标后，原有的安排怎样更新。

走查是一次性的检验，结果用于修改指引，不作为需要维护的文档。
