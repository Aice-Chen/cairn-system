# 插件

本文说明插件包的目录组织、本地与远程两种运行方式、网页端与本地代理两类客户端的兼容设计、内容通道分配以及版本与开源要求。技能与指引见[技能](skill.md)，MCP 服务端见[服务端](server.md)。

## 插件包的结构

系统仓库同时承载插件发布结构与 MCP 服务端源码：

```text
cairn-system/
├── .claude-plugin/
│   └── plugin.json              插件清单：名称、版本、userConfig（本地数据目录或远程服务地址）
├── skills/
│   └── cairn/
│       ├── SKILL.md             辅导指引正文
│       └── references/
│           └── memory-format.md 记忆格式参考
├── .mcp.json                    MCP 服务端连接声明
├── commands/                    可选增强：快速开始学习、初始化数据仓库等快捷命令
├── hooks/                       可选增强：自动填入客户端会话标识；上下文压缩或停止前提醒保存未落盘观察
├── agents/                      可选增强：预留供后续扩展模块（如后台整理）使用
├── server/                      MCP 服务端源码（Python）
├── templates/
│   └── data/                    个人数据仓库初始化模板
└── docs/                        系统设计与组件文档
```

跨平台的最小运行基线仅包含三项：插件清单、技能（`skills/cairn/`）和 MCP 连接声明（`.mcp.json`）。`commands/`、`hooks/` 和 `agents/` 均属于客户端增强层，缺少它们不影响基础辅导与记忆读写闭环。

## 两种运行方式

同一套技能文本与服务端代码支持本地进程与远程服务两种部署形态：

| 维度 | 本地方式（本地安装） | 远程方式（服务器部署） |
|---|---|---|
| 服务端运行位置 | 本机，由客户端以本地子进程（stdio）拉起 | 个人服务器（VPS），客户端通过 HTTPS 连接 |
| 数据仓库位置 | 本机目录，可直接作为本地 Obsidian 库打开编辑 | 服务器目录 |
| 适用客户端 | 支持本地 stdio MCP 的桌面/命令行代理（如 Claude Code、Codex 本地环境） | 支持远程 HTTP MCP 的所有客户端，包括 ChatGPT 网页端、Claude 网页与移动端 |
| 前置准备 | 安装插件并指定本地数据目录，无需域名、登录或 git 远端 | 部署服务端，配置域名与 GitHub OAuth 认证 |

两种方式既可单独使用，也可同时并用：例如在电脑前用本地 Claude Code 配合工作区写代码，出门或读材料时用 ChatGPT 网页端或手机端连接远程服务。并用时，本机与服务器上的两份数据仓库通过同一个私有 git 远端保持同步——`start_session` 前拉取最新提交，写操作本地提交后立即返回并在后台异步执行 `git push`。未配置 git 远端的纯本地模式下，服务端仅在本地 git 仓库提交历史。

## 网页端插件与本地代理插件的兼容机制

Cairn 同时面向限制较多的网页端插件环境（如 ChatGPT 网页端、Claude.ai）和能力完整的本地代理环境（如 Claude Code、Codex）。两类环境的平台能力差异如下：

| 能力项 | Claude Code | Claude 应用（网页、桌面、移动） | ChatGPT 网页端 | Codex 运行环境 |
|---|---|---|---|---|
| 技能（正文与按需参考文件） | 支持 | 支持（网页端需开启代码执行） | 支持 | 支持 |
| MCP 记忆服务 | 本地或远程 | 远程 | 远程 | 本地或远程 |
| 本地工作区文件与终端直接读取 | 原生支持 | 仅桌面 Cowork 模式支持 | 不支持 | 原生支持 |
| 钩子（Hooks） | 支持 | 仅 Cowork 支持 | 不支持 | 支持 |
| 命令与子代理 | 支持 | 部分支持 | 命令需转技能，无子代理 | 需转为技能形态 |
| 对话标识来源 | 钩子自动填入工具参数 | Cowork 由钩子填入；普通聊天由服务端发放短标记 | 请求自带 `_meta["openai/session"]` | 请求自带 `_meta.sessionId` |

（注：上表基于 2026 年 10 月至 11 月对 Claude 插件文档与 OpenAI 插件规范的核查及实测整理，实现阶段需针对客户端当前版本复测。）

为确保网页端与本地端均能顺畅工作且互不拖累，系统在设计上作了四点兼容安排：

1. **基线功能不依赖钩子**：阶段性记账、基于状态写入提交的时间信息计算，以及比对记录时间与状态提交时间提供新增记录线索的机制，均在“技能 + MCP 服务端”基线内完成，网页端缺少 Hooks 时不影响基本闭环运行。
2. **减少网页端写操作确认打断与等待**：网页端远程 MCP 对写入工具常有权限确认提示（及网络往返开销）。指引将记录与状态更新收敛到“明确决定当场记、学习表现待观察闭环或阶段停顿时一并记”，配合服务端后台异步拉取合并与 `git push`，减少对话中途弹窗和同步等待。
3. **环境感知按可用能力自适应**：在本地代理中，指引提示模型直接读取工作区源码、改动与运行输出以获取客观表现；在网页端纯对话环境中，模型通过 `sources/` 工具读取材料并结合对话交流判断，共用同一套学习模型。未来若为本地代理扩展专门的终端报错或测试捕获工具，仅作为感知层增强接入。
4. **处理本地工作区项目说明冲突**：在本地代理中打开带有 `CLAUDE.md` 或 `AGENTS.md` 的项目目录时，客户端会自动加载其中的要求；当这些要求与学习者在 Cairn 中的约定或当前请求冲突时，由模型直接向学习者说明冲突来源并由学习者决定（见[辅导](../design/tutoring.md#材料条件任务要求与工作区说明冲突)）。

## 信息的通道分配

输入给模型的信息分布在八个通道中，按加载时机与指令边界各司其职：

| 通道 | 加载时机 | 承载内容 |
|---|---|---|
| 技能描述 | 常驻上下文 | 触发选用本技能的场景说明 |
| 技能正文（`SKILL.md`） | 技能激活时 | 角色目标、决定权阈值、教学判断维度、教学依据、记忆读写原则 |
| 技能参考文件（`references/`） | 按需读取 | 记忆格式细节；后续按需补充的专项学习方法 |
| MCP 服务端说明 | 建立连接时 | 一两句话说明记忆服务用途，提示使用前加载 `cairn` 技能 |
| 工具说明 | 工具载入时 | 各工具的接口用途、参数约束与返回说明 |
| 工具返回结果 | 工具调用时 | 原始记忆内容（保持原有语义与来源）、材料文本、确定性系统元数据 |
| 插件钩子（仅支持端） | 特定生命周期事件 | 自动注入会话 ID；上下文压缩前提示检查未落盘的阶段记录 |
| 学习者设定 | 随 `start_session` 返回 | 学习者的背景自述、目标与协作约定（其约束效力由技能正文赋予） |

通道边界遵循两条规则：一是常驻与高频内容精简，低频格式规范按需加载；二是**行为约束仅来自技能正文与经确认的学习者决定**，服务端返回与钩子只传递事实与系统状态，不夹带隐藏教学指令。

## 版本管理与开源要求

插件与 MCP 服务端共享同一个发布版本号同步发版；数据仓库的存储结构使用独立的 `FORMAT_VERSION` 管理，日常升级提示词或服务端实现无需改动个人数据。

作为面向外部使用者的开源项目，实现与文档保持以下标准：
- **安装无需修改代码**：数据路径或远程地址通过插件配置项或环境变量提供，新数据仓库由模板初始化。
- **系统仓库不含个人数据**：系统仓库与提交历史不含作者个人学习记录，文档示例均采用虚构内容。
- **不作预先设定即可开始使用**：新用户无需预先编写设定文件即可直接提问开始学习，设定与状态在后续互动中逐步建立。
- **跨平台中立表述**：技能正文与参考文件使用厂商无关的专业中文表述；未来如需英文版可独立提供对应技能文件而不改动服务端。
