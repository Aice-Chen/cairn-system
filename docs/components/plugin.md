# 插件

本文说明插件包的结构、服务端的运行方式、各客户端的支持情况、版本安排，以及基础版与 v1 的关系。插件是把技能和 MCP 服务端的连接声明打包分发的形式；技能见[技能](skill.md)，服务端见[服务端](server.md)。各部分的确认状态见[议题与决策](../decisions.md)。

## 插件包的结构

系统仓库同时存放插件包和服务端源码，结构如下。

```text
cairn-system/
├── .claude-plugin/
│   └── plugin.json              插件清单：名称、版本、userConfig（数据目录或服务端地址）
├── skills/
│   └── cairn/
│       ├── SKILL.md             指引
│       └── references/          学习方法、记忆格式说明
├── .mcp.json                    MCP 服务端的连接声明
├── commands/                    增强：开始学习、新建学习项目、初始化数据仓库
├── hooks/                       增强：为工具调用填入对话标识；上下文压缩前提示保存尚未记录的观察
├── agents/                      增强：供扩展模块使用
├── server/                      MCP 服务端源码（Python，在 v1 的基础上修改）
├── templates/
│   └── data/                    数据仓库模板
└── docs/                        文档
```

基础功能由三项构成：插件清单、技能和 MCP 连接声明。`commands/`、`hooks/` 和 `agents/` 是增强部分，只在支持的客户端生效，缺少它们不影响基础功能。插件清单中的 `userConfig` 用于在安装时填写数据目录或服务端地址，安装因此不需要修改文件。

## 服务端的运行方式

服务端只有一份代码，支持两种运行方式。

| 运行方式 | 适用的客户端 | 数据的位置 | 认证 |
|---|---|---|---|
| 本地（stdio） | 能够启动本地进程的客户端，例如 Claude Code | 本机的数据仓库副本，可以同时作为 Obsidian 库使用 | 不需要 |
| 远程（HTTP） | 只能连接远程服务的客户端，例如 Claude 网页端和移动端、ChatGPT | 服务器上的数据仓库副本 | OAuth，沿用 v1 的 GitHub 登录 |

两种方式可以同时使用。各处的数据仓库副本通过 git 远端保持一致：服务端在加载记忆时和每次写入之前拉取，写入之后推送。本地方式不需要部署服务器，是新用户最容易开始使用的方式；需要在手机或网页端学习时，再部署远程方式。

插件的 `.mcp.json` 需要在两种连接方式之间选择。实现上可以提供两个插件变体，也可以用配置项切换，具体做法在实现阶段依据客户端的现行规范确定。

## 各客户端的支持情况

| 组成 | Claude Code | Claude 应用（网页、桌面、移动） | ChatGPT 网页端 | Codex 运行环境（Codex、ChatGPT 桌面端 Work） |
|---|---|---|---|---|
| 技能（指引、学习方法） | 支持 | 支持；网页端需要开启代码执行 | 支持 | 支持 |
| MCP 服务端（记忆服务） | 本地或远程 | 远程 | 远程 | 远程 |
| 命令 | 支持 | 支持 | 需要改写为技能 | 需要改写为技能 |
| 钩子 | 支持 | 仅 Cowork | 不支持 | 支持 |
| 子代理 | 支持 | 仅 Cowork | 不支持 | 需要改写为技能 |
| 对话标识 | 由插件的钩子填入工具参数 | Cowork 由插件的钩子填入；聊天界面不提供 | 请求中自带 | 请求中自带 |

跨客户端的基线是技能加 MCP 服务端，命令、钩子和子代理作为增强。另有两点需要注意：OpenAI 的插件门户只接受远程的 MCP 服务端，并且不展开 `userConfig`，配置需要以其他方式提供；技能的表述需要与厂商无关，同一份技能文件才能用于不同的客户端。

上表依据 2026 年 10 月核对的平台事实，以及 2026-11-15 查阅的 [Claude Code 插件参考](https://code.claude.com/docs/en/plugins-reference)、[OpenAI 插件概念](https://developers.openai.com/plugins/concepts/plugins.md)和 [OpenAI 插件提交指南](https://developers.openai.com/plugins/guides/submit-claude-plugin.md)整理。各客户端的实际行为需要在实现阶段实测。

“对话标识”一行说明服务端取得对话标记时可以使用的来源（见[服务端](server.md)中“对话标记的取得”）。

- Claude Code 和 Cowork 加载插件的钩子。钩子的输入中带有客户端的会话 ID，工具调用之前的钩子可以改写工具参数，因此可以由钩子把会话 ID 填入记忆服务工具的 `conversation` 参数。
- ChatGPT 在工具调用的 `_meta["openai/session"]` 中提供匿名化的对话标识。
- Codex 在工具调用的 `_meta.sessionId` 中提供线程 ID。这一字段见于 2026 年 10 月的实测，文档中没有记载。
- Claude 应用的聊天界面不加载钩子，请求中也没有对话标识。在这些界面上，对话标记由服务端发放，由模型带上。

这一行依据 2026 年 10 月的实测，以及 2026-11-16 查阅的 [Claude Code 钩子参考](https://code.claude.com/docs/en/hooks)、[Claude 插件构建说明](https://claude.com/docs/plugins/build)和 [OpenAI 插件参考](https://developers.openai.com/plugins/reference)整理。钩子的做法尚未实测，各标识在长时间内是否稳定也需要在实现阶段确认。

## 内容的放置

提供给模型的内容按加载时机分布在七个通道，每类内容放在与其加载时机相称的通道。

| 通道 | 加载时机 | 放置的内容 |
|---|---|---|
| 技能描述 | 始终在上下文中 | 何时使用本技能 |
| 技能正文 | 技能被选用时 | 指引：角色与目标、教学原则、记忆的使用、学习方法的取用方式 |
| 技能参考文件 | 模型按需读取 | 学习方法、记忆格式说明 |
| MCP 服务端说明 | 连接时 | 用一两句话说明服务的用途，并指明使用前先加载技能 |
| 工具说明 | 工具被加载时 | 该工具的用途、参数和返回 |
| 工具结果 | 调用时 | 事实：记忆内容、时间信息、需要注意的事实 |
| 学习者设定 | 随 `start_session` 返回 | 学习者的情况、目标和约定；其效力在技能正文中说明 |

分配的原则有两条。第一，对所有学习者适用、且每次辅导都需要的内容放在技能正文；只在特定情形下需要的内容放在参考文件，按需读取。第二，行为指令只来自技能和学习者设定，工具说明和工具结果只提供事实。学习者设定虽然经由工具结果到达模型，但技能正文已经说明它等同于学习者的指令。

## 版本

插件和服务端使用同一个发布版本号，一同发布。记忆格式使用独立的版本号，记录在数据仓库的 `FORMAT_VERSION` 中；格式变更时提高该版本号，并提供迁移说明或迁移脚本。插件的日常升级因此不涉及数据，只有格式变更才需要迁移。

## 与 v1 的关系

基础版在 v1 服务端的基础上修改。

| v1 的部分 | 基础版的处理 |
|---|---|
| 传输层（HTTP 和 stdio）、GitHub 登录、git 同步 | 保留 |
| 工具 | 学习材料工具保留，其余由页面工具和 `add_record_entry` 取代，见[服务端](server.md)中“与 v1 工具的对应” |
| 数据目录 | 改为 `settings/`、`state/`、`records/`，记忆格式版本由 1 提高到 2，见[数据仓库](data-repo.md)中“与 v1 数据目录的对应” |
| `harness/guide.md` 和 `harness/standards/` | 分别改写为技能正文和技能参考文件 |
| 新增 | 链接解析、索引生成、时间信息计算、版本校验 |

数据仓库中已有 v1 格式的内容时，在实现阶段提供一次性的转换脚本。

## 开源的要求

Cairn 以开源项目的形式发布，供他人安装使用。这对实现提出以下要求，在设计阶段即予以考虑。

- **安装不需要修改代码。** 配置通过插件的 `userConfig` 或环境变量提供；数据仓库由模板创建。
- **系统仓库不含个人数据。** 个人的记忆只存在于各自的数据仓库中；示例使用虚构内容。
- **不作任何设定即可开始使用。** 新用户不写设定时，辅导按指引和学习方法进行；学习者可以随时用设定调整。
- **表述与厂商无关。** 指引和学习方法不依赖特定厂商的术语，同一技能可以用于不同的客户端。
- **文档齐备。** 安装说明、记忆格式说明、工具参考和设计文档随仓库提供。
- **语言。** 当前的指引和学习方法为中文；英文版本可以作为独立的技能文件提供，不影响服务端。

许可证、仓库的最终命名和发布渠道在实现阶段确定。
