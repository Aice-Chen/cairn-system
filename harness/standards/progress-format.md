# progress 格式

## 用途

每个资源一份，记录这个资源的基本信息、结构，以及学习者在其中的进度。
它是"学到哪里"的唯一来源；掌握程度记录在 concepts.md。

## 结构

- frontmatter：resource 为资源名，与 sources/ 下的文件夹名一致。
- 基本信息：来源（课程主页、仓库地址、文件下载链接）、作业代码仓库路径、学习目的。学习目的决定讲解的深度和取舍，比如"只学系统相关部分"或"作为全局地图通读"。
- 大纲：按资源自身的结构逐项列出（课程按讲和作业，书按章，系列文章按篇）。每项写明对应的材料路径和状态，需要时加备注，如作业截止日期。
- 当前位置：下次从哪里继续，每次收尾时更新。
- 说明：跳过了哪些部分及原因、不属于大纲任何一项的材料、进度上的特殊情况等。

## 材料列

写该项对应材料在 sources/<资源名>/ 下的完整相对路径，例如 `week03/lecture-05.pdf`。一项可以对应多个路径，也可以暂时空着（比如课件还没发布）。
也可以登记文件夹，写成以 `/` 结尾的路径，例如 `lab2/`，表示整个文件夹都属于这一项。一讲的材料较多，或者包含示例代码这类零散文件时，登记文件夹更方便。作为材料的代码仓库，同样登记它的文件夹路径。

新材料是靠路径来发现的：一个文件如果它的完整路径、以及它所在的各级文件夹都没有出现在 progress 里，就是还没登记的新材料。所以每个材料都要出现在 progress 里：属于某一项的写进大纲，其余的（课程大纲、参考资料等）列在说明里。
已登记的文件夹里后来放入的文件，会作为"已登记文件夹中新增或修改的文件"报告，需要时把它登记到对应的项。登记过的路径如果已经不存在（文件被移动或改名），会被报告为失效，按新路径重新登记即可。

## 状态

- 未学：还没开始。
- 接触过：看过或上过课，但没有在系统里学习过，因此没有观察记录。
- 进行中：已经开始，还没学完。
- 已学：在系统里完整学过一遍。
- 跳过：决定不学，在备注中写明原因。

## 示例

以下是格式示例，讲次标题和状态仅作示意。

```markdown
---
resource: embedded-101
---
# 嵌入式系统导论

## 基本信息
- 来源：课程主页（课件需登录下载）
- 作业代码：~/code/embedded-101-labs
- 学习目的：跟上课程并完成 lab，重点理解 STM32 外设的工作机制

## 大纲
| 部分 | 材料 | 状态 | 备注 |
|---|---|---|---|
| Lecture 1 课程介绍 | lecture-01.pdf | 接触过 | |
| Lecture 2 GPIO | lecture-02.pdf | 接触过 | |
| Lecture 5 外部中断 | lecture-05.pdf | 进行中 | |
| Lecture 6 定时器 | | 未学 | 课件尚未发布 |
| Lab1 | lab1/ | 已学 | 截止 11/3 |
| Lab2 | lab2/ | 进行中 | 截止 11/3 |

## 当前位置
Lab2 后半：按键消抖。

## 说明
- 第 1–4 讲在系统建立前已上过课，没有学习记录。
- syllabus.pdf 为课程大纲。
```
